# EDOS Future Ideas

## Done

- **The std fork moved from Rust 1.96 to 1.99, and std stopped declining what
  the kernel already offered** - three months of upstream (13,491 commits) cost
  nine one-hunk conflicts and seven pieces of semantic drift that no conflict
  marks: the futex module moved under `sys/sync/`, `BorrowedCursor` gained an
  element type, `sys/alloc` backends became free functions, `crate::sealed`
  gave way to `pub impl(self) trait`, and pointers handed to the kernel now
  need `expose_provenance`. `doc/rust-fork-rebase.md` carries the measurements
  and the traps. Auditing what the backend answered afterwards found eight
  places where the mechanism existed and std refused to use it: `yield_now` did
  nothing at all, which had `play` busy-spinning on a full audio ring buffer
  and the compositor spinning the tail of every frame; `available_parallelism`
  gave up beside a `/proc/cpuinfo` that `nproc` already reads;
  `Child::kill` and `set_cloexec` reported unsupported next to `SYS_KILL` and
  `F_SETFD`; `permissions().readonly()` threw away the bit `stat` delivers;
  `Command::output()` and `Stdio::null()` failed outright; and `Debug for File`
  was a `todo!()` that panicked. `SYS_SCHED_YIELD` and `/dev/{null,zero,full}`
  are the two new pieces of kernel behind them. `set_perm` went the other
  way and now reports Unsupported: nothing writes attributes back, and
  answering `Ok` left a caller believing a file it had just made read-only was
  protected.

- **`netstat`, and the `/proc/sockets` it needed** - the connection table was
  reachable only from inside the kernel, so nothing could answer "who is
  listening" or "why can this port not be bound". `/proc/sockets` publishes
  every TCP connection the stack tracks, then every port-table binding without
  a connection of its own, as `PROTO RECVQ SENDQ LOCAL FOREIGN STATE`. That is
  a different set from `/proc/<tid>/fd`: a connection outlives the descriptor
  that made it, so `TIME_WAIT`, `FIN_WAIT2` and a stranded `SYN_RECV` appear
  here and nowhere else. `netstat` renders it with `-a`, `-l`, `-t`, `-u`, and
  reads `/proc/net` for `-i` and `-r`. It made the two open TCP bugs visible on
  the first run: the connection lost to the ARP-pending drop after boot sits in
  `SYN_RECV` with one unacknowledged byte, and stays in the list forever
  because the accept queue has no half-open timeout.

- **`httpd`, and the port table that unbound its own listener** - a web server
  over the guest filesystem, one thread per connection, `GET`/`HEAD`,
  directory listings, an index file, content types, path-traversal rejection
  after percent decoding, and a 301 for a directory without its trailing
  slash. Being the first program to accept more than a couple of connections,
  it found that two of the three socket close paths removed a port-table entry
  by port alone, unbinding the listener as soon as any accepted connection
  ended, and that a retransmitted SYN pushed a second half-open entry into the
  accept queue and never gave the slot back. Both fixed; `unbind_port` and
  `port_key` in `kernel/src/net/socket.rs` now hold the ownership rule in one
  place.

- **`nc`, and the hang-up `poll` refused to report** - both ends of a TCP
  connection over one relay loop that polls standard input and the socket
  together: `nc host port` connects, `nc -l port` listens and accepts, with
  `-knvz`, `-w`, `-q`, `-p` and `-s`. End of input half-closes via
  `SYS_SHUTDOWN`, so `echo hi | nc host 7` still receives the answer; that
  syscall had been implemented and unreachable. Two kernel fixes came out of
  the first run: `PollState::matches` demanded that a caller ask for hang-up
  before it would report one, against POSIX, which makes POLLERR/POLLHUP/
  POLLNVAL output-only; and a drained pipe with no writer left reported only
  hang-up and never readable, though a read there returns end of file at once.
  Also `edos_lib::net::send_all`, replacing two open-coded retry loops that
  treated the "window full" zero-length write as a failure.

- **`lsof`, and the `/proc/<tid>/fd` it needed** - the descriptor table lived on
  `UserThreadInfo` and nothing published it, so "which process still has this
  open" was unanswerable. procfs now renders one row per descriptor
  (`FD TYPE MODE POS NAME`), a table rather than Linux's directory of symbolic
  links because a pipe end, a PTY side and a socket have no path. Pipes and
  PTYs carry the shared object's address, so both ends pair up across
  processes; sockets carry protocol, endpoints and TCP state.

- **`sed`, and the backslashes the shell was eating** - a stream editor over
  its own backtracking regex engine: POSIX BRE, ERE under `-E`, and the GNU
  extensions scripts actually use. `s`, `y`, `p`, `d`, `q`, `=`, `a`, `i`, `c`
  and `{}` blocks, addressed by line, `$`, `/re/`, ranges of either and `!`,
  with `-n`, `-e`, `-f` and in-place `-i`. Fifty-two cases were diffed against
  GNU sed on the host before it ever booted. Testing it turned up the reason
  every sed one-liner would have looked broken: `parse_command` in `edos-sh`
  stripped backslashes inside single quotes, so `'s/\(.*\)/\1/'` arrived as
  `s/(.*)/1/`. Quote removal now follows POSIX 2.2.2/2.2.3.

- **`pmap`, and the address space `/proc` never showed** - `status` counted
  VMAs and totalled their size; nothing said what any one of them was. The new
  `/proc/<tid>/maps` prints one line per VMA — range, `rwxp`, size asked for,
  size actually mapped, and what backs it (`anon`, `stack`, `tls`, `shm:<id>`,
  `phys:0x..`, `file:<mount>:<ino>+<off>`) — and `pmap` renders it, with `-x`
  for the end address and `-q` for the bare list. The residency column is a
  page-table walk clipped to one range (`MemoryManager::resident_bytes_in`),
  so a mapping's demand paging is visible: a shell asks for 8532 KiB and has
  220 KiB. The per-thread files now live in a `PROCESS_FILES` table like the
  global ones, so a new one is a row rather than four match arms.

- **`sntp`, and the clock the kernel could not be told** - the RTC is sampled
  once at boot at one-second resolution and everything after it is HPET ticks,
  which left the guest around 1.4 s slow with no way to correct it. One UDP
  round trip (RFC 4330) gives the offset and delay; `-s` acts on it through the
  new `SYS_CLOCK_SETTIME`, which stores an atomic correction rather than
  re-pinning, so monotonic time is untouched. Takes several servers, `-u` for
  UTC, `-t` for the timeout and `-p` for the port, defaults to `pool.ntp.org`,
  and refuses a reply whose originate timestamp is not the one it sent.

- **`pstree`, the thread table as a forest** - `/proc/processes` has carried a
  PPID column that every reader printed as a number, so the structure
  `edos-init` supervises with, and the fact that a shell's background jobs are
  its children, were invisible. Draws the classic aligned tree, collapses runs
  of identical siblings into `N*[name]`, and takes `-p`/`-g` for pids and
  process groups, `-u` for user threads only, `-n` to sort by pid, `-c` to keep
  identical siblings apart, `-l` for the whole spawn path, `-U` for box-drawing
  lines, and a PID operand to root the tree anywhere.

- **`less`, a pager** - holds the whole text and moves a window over it: j/k and
  arrows, space/b by the screen, d/u by half, g/G, left/right for output wider
  than the terminal, `/pat` and `?pat` search with every match on a line
  reverse-videoed, `n`/`N`, `:n`/`:p` across several files, `-N` line numbers,
  `-i` case-insensitive search and `h` for the key list. `dmesg | less` works
  because the keys are read from stderr when stdin is the pipe carrying the
  text; with no terminal at either end it behaves as `cat`. The escape-aware
  column splitting it shares with `watch` moved into `edos_lib::term`.

- **`watch`, a command on a timer** - re-runs a command every N seconds and
  paints its output over the previous frame, with `-d` reverse-videoing the
  columns that changed since the last run, `-x` to skip the `sh -c` the command
  otherwise goes through, and `-e` to stop on the first non-zero exit. Escapes
  in the watched command's own output are parsed out as zero-width, so clipping
  to the screen width and diffing both count real columns. Needed SGR 7/27
  (reverse video) in the terminal widget, which had never been implemented.

- **`ln`, and links you can see** - `ln -s` creates symbolic links from the
  shell for the first time: one target into the working directory, one target
  to a named link, or several targets into a directory, with `-f` to replace
  an existing non-directory and `-v` to report each one. Hard links are
  refused with a reason: the kernel has no `link(2)` and EFS inodes carry no
  link count. `ls` now marks a symbolic link `@` and a directory `/`, and
  `stat` describes the link itself rather than its target.

- **Focus follows a closed window again** - destroying a window moved keyboard
  focus in the registry but never sent `FocusGained` to whoever inherited it,
  so the terminal painted focused and dropped every keystroke once any GUI
  program had been opened and closed; click-to-focus could not repair it,
  because a click on the window the registry already names sends nothing.
  `destroy_window`/`destroy_windows_for_pid` now return the heir and both
  callers deliver the event, covering the orderly close and the killed process
  alike.

- **`imgview`** - a BMP viewer, and the first ordinary GUI application the
  system has: one window, one image, `f` to fit it to the window and `1` to
  show it at one image pixel per screen pixel. It decodes with the same
  `edos_render::image` the compositor uses for a wallpaper; what it adds is
  `fit_size`/`scaled_to_fit` beside the existing scale-to-cover, over one
  shared bilinear resampler.

- **`nproc`** and the `/proc/cpuinfo` behind it - the CPU count was not
  exposed to userspace at all, which is odd for an SMP kernel. The file reports
  vendor, brand string, family/model/stepping and the feature flags the kernel
  depends on, one block per online CPU, then `cpus detected` and `cpus online`.
  The two differ when an AP fails to start, so `nproc` prints the online count
  and `--all` the detected one. Completes Phase 4 of the userspace roadmap.

- **`tcpecho`** - a TCP echo server over `bind`/`listen`/`accept`, the first
  user of the listen side of the stack. Serves one connection at a time so the
  kernel backlog holds the next; `-p`, `-a`, `-1`, `-q`. It found two kernel
  bugs immediately: `sys_listen` took the port table under the socket lock
  (the rank tracker caught it), and closing an accepted socket removed its
  listener's port-table entry so the second connection got RST. Both fixed;
  see `doc/WORKING-NOTES.md`.

- **`snake`** - the terminal game on a timer, and the first program here whose
  clock nobody drives: one `poll` on stdin per frame with what is left of the
  tick as its timeout, so a key answers instantly without moving the snake or
  pushing the next move back. Arrows or wasd/hjkl, `p` pauses, `r` replays,
  `-s` sets the starting tick and derives the speed ramp, `-w` wraps at the
  walls. Refuses to run without a terminal.

- **`top`** - the thread table on a timer, in raw mode: live CPU share per
  thread from the growth of the kernel's monotonic `CPUms`, sortable by cpu,
  memory, total time or pid, kernel threads hideable with `u`. `-b`, `-n` and
  `-d` give the batch form, and a run whose stdout is not a terminal turns
  itself batch. Its parse of `/proc/processes` moved to `edos_lib::procinfo`,
  shared with `edos-procview` - which had silently been reading one column
  behind since `PGID` was added to that table.
- **`tar`** - ustar (POSIX.1-1988) create, list and extract, with `-v`, `-C`,
  and `-f` where `-` or no flag means the standard stream, so
  `tar -cf - dir | tar -xf - -C dest` copies a tree. Regular files,
  directories and symbolic links; a member whose name would escape the
  extraction directory is refused. Reads and writes what GNU tar does, checked
  in both directions rather than only round-tripped against itself.
- **Local time, and `date`** - the session carries a fixed UTC offset in `TZ`
  (an ISO 8601 offset, not a POSIX zone rule: there is no zone database and no
  DST), `edos_lib::time::local_time` is the single place that applies it, and
  the panel clock and `cal` read it. `programs/date` prints local time, `-u`
  prints UTC, and `+FORMAT` covers a strftime subset. Getting it to the panel
  meant giving the session an environment: `edos-init` and the terminal spawned
  through `SYS_SPAWN`, which passes no envp at all, and both go through
  `process::spawn_with_env` over `SYS_SPAWN2` now. See `doc/WORKING-NOTES.md`.
- **Shell job control** - Ctrl+Z suspends a foreground job, `jobs` lists it as
  Stopped, `fg` and `bg` resume it, and every stage of a pipeline shares one
  process group so a single Ctrl+C reaches all of it. `spawn_pipeline` returns
  the stage pids instead of waiting, a background external job is spawned
  directly rather than forked, and the shell takes the terminal back after
  every job. Two kernel halves went with it: an untraced `waitpid` that blocks
  until the child exits *or* stops, and `SIGCONT` clearing the target's
  `stopped` flag at delivery. See `doc/WORKING-NOTES.md`.
- **Signals grew up** - five kernel items, all covered by `programs/sigtest`.
  Process groups (`setpgid`/`getpgid`, `tcsetpgrp`/`tcgetpgrp`, `kill` with a
  negative pid) so Ctrl+C reaches a pipeline rather than one stage of it;
  `SIGSTOP`/`SIGTSTP`/`SIGCONT` with Ctrl+Z, a thread suspending at the same
  boundary `killed` uses so a suspended process never holds a filesystem lock,
  and `waitpid` reporting a stopped child; real userspace handlers, delivered
  by building a frame on the user stack at the syscall-return boundary and
  unwound by a new `sigreturn`, restoring the whole context including the
  interrupted call's return value; `SIGPIPE` on a write to a pipe with no
  reader, which used to buffer into the kernel heap forever; and `SIGCHLD` to
  the parent on exit. A thread that never syscalls never runs a *handler* --
  default actions still reach it from the timer tick.
- **strace** - the kernel records syscall entries and returns for marked
  threads into a ring a tracer drains, and `programs/strace` formats them.
  No ptrace: dispatch in `syscalls/mod.rs` is one choke point, so the mark is
  one relaxed load next to the `last_syscall` store already there. Marks are
  generation-stamped, so ending a session invalidates every outstanding one
  with a single increment instead of walking the thread table, and a tracer
  that dies releases the session from `thread_exit`. Children are followed,
  string and buffer arguments are copied out of user memory (in on entry,
  out on return, sized by the return value), and a call that has not
  returned prints `<unfinished ...>`, which is the answer to "the program is
  doing nothing". `/proc/syscalls` publishes the kernel's own syscall and
  errno tables so the formatter holds no second copy that could rot.
  Written up in `doc/strace.md`.
- **Symbolic links resolve in the mount namespace** - a filesystem walks
  paths from its own root and cannot see the mount table, so it no longer
  resolves a link target at all: it reports where the link pointed and the
  VFS says what that names, restarting from the VFS root and crossing onto
  whatever mount the target lives on. Fixes an absolute target being looked
  up under the link's own filesystem (`iotest /tmp` stopped at test 10),
  a relative target whose `..` walked out of the mount, and a target that
  landed on something mounted deeper. `LinkMode` carries the follow /
  nofollow distinction the VFS previously left to each filesystem, so
  `unlink`, `readlink` and `rename` act on the link and everything else
  acts on what it names. Escalation is error-driven (`Error::LinkEscape`),
  so a path with no links costs exactly one walk as before.
- **AHCI ATAPI bounds its reads by the transferred count** - the command
  header's `prdbc`, which the HBA writes on completion, instead of assuming
  the full allocation length arrived out of a pooled DMA buffer that is not
  zeroed between owners. Same defect previously fixed in xHCI descriptors
  and USB mass storage. A short INQUIRY, READ CAPACITY or READ(10) is now
  rejected rather than padded with the previous owner's bytes; the boot ISO
  is an ATAPI port on q35, so this runs on every boot.
- **The panel is addressable by name** - its buttons are not windows, so it
  publishes them itself: the panel writes its controls to `/dev/klog`
  whenever its layout moves and the applications menu writes its rows as it
  opens, tagged like the window dump. `scripts/edos-vm` grows `panel` and
  `press <name>` and resolves `launch` rows by label, with no layout
  constant left in the script.
- **edos-procview** - a graphical process viewer over `/proc/processes`,
  `/proc/<tid>/status` and `/proc/meminfo`: a live table with keyboard and
  pointer selection, a detail line per process, and kill behind a
  confirmation.
- **Per-process memory in procfs** - the gap `edos-procview` ran into.
  `/proc/processes` grows an RSS column and `/proc/<tid>/status` a `VM Size`
  and a `Resident` line. Resident is counted from the page tables on read
  rather than tracked in a field: a page enters a user address space from
  demand paging, COW, mmap, shared memory and the loader and leaves from as
  many places again, and a counter maintained at each of them drifts the first
  time one is missed. The walk descends only into present entries, so a lazily
  faulted mapping costs one skipped entry rather than a probe per page.
- **fsbench** - `programs/fsbench` measures filesystem throughput and latency
  across idioms (write/read at 512B..1MiB, BufWriter, fs::write, pwrite,
  random, mmap, fsync, metadata) and three depths (memfs, raw block device,
  EFS). Time-budgeted so the suite finishes whatever the throughput; verifies a
  position-dependent pattern after writing; prints the delta of every relevant
  /proc counter. `raw`/`rawwrite` modes hit the block device directly. Docs:
  `doc/fsbench.md`; what to optimise next: `doc/STORAGE-ROADMAP.md`.
- **Storage throughput round (2026-08-09)** - coalescing contiguous blocks into
  one command wherever a path owns a long exclusive run: block-cache reads
  (37 -> 886 MiB/s at 1 MiB), block-cache whole-page writes (44 -> 543 MiB/s
  preallocated), EFS file-data flush, and the journal ring. Plus `efs-mkfs`
  zeroing in 1 MiB chunks. `edos-install` 4.3s -> 2.8s; first fsync after a
  heavy write phase 34s -> 0.6s. Sequential bandwidth now sits either side of
  SATA III line rate; what is left is per-command cost at 4 KiB.
- **Network stack** - e1000e driver with MSI-X, ARP, ICMP, UDP, TCP (retransmit,
  flow control), DHCP, DNS resolver, HTTP client, IP fragment reassembly
- **std::net** - TcpStream, UdpSocket wired up in the Rust std fork
- **Socket poll wakeup** - PollEntry registered, indefinite poll wakes on data arrival
- **Custom filesystem (EFS)** - ext2-inspired with extents, replaces FAT32 as root FS.
  Spec in doc/efs.md, shared crate in libs/efs-common/, kernel driver, host mkfs tool
- **USB stack** - xHCI, HID (keyboard/mouse), mass storage with FAT32 mounting
- **Virtio-GPU** - 2D driver, dirty-rect transfers, blob resources, hardware cursor
- **Shell scripting** - Functions, control flow, heredocs, command substitution, tab completion
- **PTY subsystem** - Line discipline, canonical/raw modes
- **Graphics pipeline** - VRAM double buffering, SHM zero-copy compositing, Ayu Dark theme
- **COW fork** - Per-frame refcounting, PTE BIT_9 marker, COW fault handler.
  Shell background jobs (&), subshells (()), jobs/wait builtins
- **Sound** - Intel HDA driver with CORB/RIRB codec commands, BDL DMA ring,
  /dev/dsp device node, userspace `play` command for WAV files
- **AHCI NCQ** - FPDMA commands (32 concurrent slots), per-slot DMA pools,
  lock-free slot allocation, mode exclusion for NCQ/non-NCQ coexistence
- **VFS per-inode locking** - Per-inode RwLock with dentry cache (256 entries).
  Single locking layer in vfs.rs (vfs::read/write/file_info/etc.).
  FileSystem trait all &self, drivers manage internal locks.
  Parallel boot loading (3 binaries via NCQ, 113ms for 11.8MB).
- **Inode-based FS fast path** - read_bytes_ino/write_bytes_ino/file_size_ino
  on FileSystem trait. VFS tries inode-based first, falls back to path-based.
  EFS and Memfs skip directory tree walks on read/write for open files.
- **USB HID ISO keyboard fix** - Fixed 4 wrong/missing keycode mappings for
  European ISO keyboards (< > º ç ´).
- **Shell quoted redirect fix** - parse_command tracks quoted tokens,
  extract_redirects skips them. echo "<" > file works correctly.
- **Fd-numbered redirection** - `2>file`, `2>>file`, `2>&1`, `1>&2` and
  `&>file`, per pipeline stage as well as per command. Redirections are an
  ordered op list resolved left to right, so `>f 2>&1` and `2>&1 >f` differ as
  they should. `>` now truncates, and O_TRUNC is ignored on non-regular files.
- **Shell pathname expansion** - `*`, `?` and `[...]` matched per path
  component over readdir, for command arguments and `for` word lists. No match
  passes through unchanged, quoted and escaped words are literal, `*` skips
  dotfiles. `ls` now takes many operands and non-directory ones, which globbing
  immediately required.
- **Heap expansion race fixes** - Lazy vmalloc fault handler, expansion
  serialization (AtomicBool), per-CPU heap freelists (6 size classes,
  16 slots/CPU, batch refill/drain). Removed heap warmup workaround.
- **TLB shootdown IPIs** - TlbShootdown interrupt vector, global
  TlbFlushRequest with atomic bitmask acks. Deferred frame free in
  munmap (unmap PTEs, shootdown, then free). COW fork uses
  tlb_shootdown_all. CPU topology tracking in smp.rs.
- **FSGSBASE** - CR4.FSGSBASE enabled with CPUID probe + fallback.
  get_percpu_data() uses rdgsbase (~1 cycle) instead of rdmsr (~30).
- **Limine 0.6 + bootloader v11** - Crate 0.5->0.6 API migration,
  bootloader v9->v11 for base revision 6. RSDP/DTB addresses virtual
  in rev6 (converted to physical). HHDM now 1GB huge pages.
- **HHDM-based process spawn** - Eliminated CR3 switching during ELF
  loading. Writes to child address space go through HHDM translation
  (copy_to_user/zero_user/write_val_to_user helpers on MemoryManager).
  Fixes TLB shootdown timeouts caused by 100+ms interrupts-off in
  do_spawn. Boot stack guard page removed (inside HHDM huge pages).
- **Dep bumps** - acpi 6.1.1, bytemuck 1.25.0, bitflags 2.11.0
- **O_TRUNC support** - Wired OpenOptions::truncate() through edos_rt
  OpenFlags::TRUNCATE (0x200) to kernel sys_open. File::create and
  std::fs::write now correctly truncate existing files.
- **Per-file fsync** - SYS_FSYNC syscall (14) with per-inode flush path.
  EFS/FAT32 flush_inode() flushes drive write cache only (skips
  superblock/BGD/FSInfo). File::sync_all()/sync_data() reach it through
  Rust std; the std fork's sys/fs/edos.rs stubs returned Ok(()) without
  calling anything until 2026-08-09, so every caller before that was
  told its data was durable when nothing had been flushed.
  AHCI FUA detection (IDENTIFY word 84 bit 6) and FUA write
  commands (WRITE DMA FUA EXT, WRITE FPDMA QUEUED FUA) added for
  future use.
- **AHCI zero-copy DMA** - Build PRDT entries directly from caller
  buffer physical pages, eliminating per-I/O memcpy through DMA pool
  pages. Translates virt-to-phys per page via memory_mapper(),
  merges contiguous frames, falls back to pool-copy on translation
  failure or odd-aligned buffers. Applied to NCQ read/write,
  NCQ batch read, and legacy ATA read/write paths.
- **Demand paging** - VMA subsystem (VmaSet replaces MemoryMapping/
  MemoryRegion), anonymous zero-fill on fault, lazy ELF loading
  (segments faulted from stored Arc<Vec<u8>>), lazy stack growth.
  MemoryManager owns VmaSet (like Linux mm_struct) so copy_to_user
  can demand-fault during thread construction. Shared fault_in_page
  used by both IST handler and HHDM translate path.
- **Per-inode page cache (EFS file data)** - Linux-style address_space
  per VfsInode: BTreeMap<page_idx, Arc<CachedPage>> + BlockingMutex.
  PageCacheOps trait on FileSystem (fill_page, fill_pages_bulk,
  flush_page, update_size). Bulk fill path does one multi-block AHCI
  read then distributes into per-page entries (Linux readahead style).
  Direct AHCI I/O bypassing BlockDevice (INVARIANT, preserved). Stays
  write-through for now; file-data write-back can come later.
- **Block-device page cache (storage roadmap step 1)** - 4 KiB-page
  cache keyed by (device_id, block), 8 LRU shards x 256 = 2048-page
  ceiling. Replaces the old 512 B sector LRU on BlockDevice. EFS
  read_block/write_block, inode/BGD/bitmap reads, and FAT32 metadata
  all go through it. Per-page write_lock serializes RMW. /proc/block_cache
  exposes hits/misses/evictions. inode_cache removed from EfsDriver.
- **Write-back metadata cache (storage roadmap step 2)** - write_page /
  write_partial_page mark dirty + return; background block_writeback
  kthread flushes every 5s or on kick. flush_requested / flush_completed
  AtomicU64 counters form a race-free sync barrier. flush_device calls
  AHCI FLUSH CACHE after writeback (fsync reaches platter). sys_sync
  (162) added; /bin/sync tool. system-mount wall: 1379ms -> 972ms.
  CRASH SAFETY: write-back without journal means crash mid-mkdir can
  corrupt the FS. Journal (step 3) fixes.
- **Kernel lifetime logging** - spawn: / exit: log lines with load time
  (do_spawn duration), wall time (thread creation -> exit), cpu time
  (scheduler accounting), and demand_faults count. Revealed ~140x
  cold/warm page-cache speedup on binary loads and mkdir being the
  bottleneck in system-mount.
- **Kernel debug_asserts** - is_canonical() pointer checks on
  intrusive_list push_back/push_front/unlink. pin_count==0 on
  CachedBlockPage::drop. Frame-alignment checks in the block cache.
  spawn_thread state check. Zero release cost; catches pointer
  corruption / leaked guards early.
- **pick_sched lapic_id fix** - SCHEDULERS is keyed by lapic_id, not
  sequential index. Previous code iterated 0..num_cpus treating i as
  lapic_id; works on QEMU, broken on real hardware with sparse lapic
  IDs. Now iterates values directly.
- **EFS metadata journal (storage roadmap step 3)** - jbd2-style WAL
  for crash-safe metadata. On-disk ring (default 16 MiB, reserved at
  mkfs). TxHandle RAII wraps every metadata op (create/remove file/dir,
  rename, truncate); enrolls dirty pages + revoke records for freed
  blocks. Committer kthread seals active tx every 1s, writes
  descriptor+data+revoke+FUA commit to the ring. Writeback gated:
  dirty pages don't flush to home location until their tx is committed.
  Two-pass replay on mount: pass 1 builds revoke set, pass 2 applies
  committed data blocks (skipping revoked). CRC-verified commits,
  magic-escaped data blocks. DescriptorEntry 16B with flags field.
  Block-level ring capacity tracking (head_block/tail_block).
  sys_sync/sys_fsync force-commit with 30s timeout.
  INCOMPAT_JOURNAL feature bit; old images must be reformatted.
  /bin/sync tool. system-mount wall: 1379ms -> 808ms.
- **VFS page_cache_read EOF fix** - page_cache_read returned full count
  bytes past EOF (zero-filled cached pages). read_to_end looped
  forever. Fix: VFS read() clamps to file_size_ino before page cache.
- **EFS file-data I/O path consistency** - write_via_extents and all
  directory-data reads now correctly use their designated paths:
  file data via direct AHCI (matching read_via_extents), directory
  data via read_dir_data_cached (through block page cache, matching
  write_block). Prevents stale-data bugs with write-back metadata.
- **Boot hang fix** - Root cause was switch_to_kernel_page() calling
  tlb_flush_all_including_global() unconditionally (even when CR3
  didn't change), creating a TLB storm during parallel boot that
  triggered cascading vmalloc faults. Combined with IST re-entrancy
  (nested page fault on IST 1 clobbered the outer handler's stack
  frame), this caused all CPUs to get stuck. Fix: removed the
  unconditional global TLB flush (Cr3::write already flushes
  non-globals), and moved page fault handler off IST onto the
  regular kernel stack so nested faults work naturally. Double fault
  handler retains its own IST for stack overflow protection.
  20/20 boot test passes (was ~1 in 5 failure rate).
- **Scheduler park/wake race fix (2026-04-13)** - Added wake-pending
  token (Thread.wake_pending: AtomicBool). Wakers signal_wake() before
  probing state; parkers consume_wake_pending() after CAS to Parked/
  Sleeping and revert to Running if set. Closes the lost-wakeup race
  for thread_park, thread_park_while, and thread_sleep at the primitive
  level. wake_thread_slow + wake_thread_from_irq collapsed to one
  do_wake; retry loop / MAX_RETRIES / spin_loop deleted. New transition
  Sleeping->Running for sleep abort. thread_park_while now LOOPS on
  spurious-wake (token consumed but closure still says park) so callers
  without their own outer loop (sys_waitpid in particular) are correct
  by contract. Fixes the intermittent boot hang documented in
  doc/bugs/2026-04-13-sched-park-wake-missed-wakeup.md
  AND the shell-dies-after-`ls` symptom seen during testing. Debug
  visibility: Thread.last_syscall + dump_threads.gdb shows SYSCALL and
  WP columns per thread.
- **EFS host fsck (storage roadmap step 4)** - `tools/efs-fsck/` host
  tool: SB/BGD cross-check, journal replay (port of kernel's two-pass
  algorithm via shared `libs/efs-common/journal_parse.rs`), inode scan
  with extent validation, block+inode bitmap rebuild and leak/double-
  claim detection, directory-tree walk with `.`/`..` and link-count
  reconciliation. `--repair` opts into 5 fix classes (leaked block
  bits, leaked inode bits, BGD/SB free-count sums, link-count fixes,
  orphan deletion) with per-class prompts (`-y` to auto-accept) and
  Linux-style exit codes (0/1/4/8/16). `fsck_in_progress` byte stolen
  from superblock reserved area protects against killed-mid-repair
  reruns (`--force` to override). Double-claim guard skips bitmap
  clears for blocks also held by live inodes. 8 integration tests +
  `doc/efs-fsck.md`.
- **Lazy ELF relocation (2026-04-13)** - Replaced eager R_X86_64_RELATIVE
  pass with on-demand patching driven by the page fault handler. Per-process
  Arc<RelocTable> with per-page bucket index parsed at load_elf; fault path
  early-COWs reloc-target pages (allocate private frame, copy from cache,
  apply relocs, map writable, never patch shared cache). Partial-last-file-
  page pre-fault has relocs applied at load time (lazy path can't fire on
  already-mapped pages). Cold-spawn /bin/sh from terminal: 238ms -> 162ms
  (-32%). Boot-time parallel loads unchanged (already I/O-bound). Foundation
  for future dynamic linker. Does not yet shrink time-to-/bin/sh because
  boot-load kthreads are already parallel and AHCI-bound; gain is on serial
  cold spawns.
- **File-backed mmap (MAP_PRIVATE + MAP_SHARED)** - VmaBacking::FileBacked
  with Arc<VfsInode> + Arc<CachedPage>-per-page on the VMA. MAP_PRIVATE
  installs read-only + COW_BIT, writes fault into anon via the existing
  COW handler. MAP_SHARED installs writable, dirty-marks unconditionally
  on first fault, flushes via PageCacheOps::flush_page on msync, munmap,
  process exit, and periodically from the writeback kthread (global
  DIRTY_INODES Weak registry, IrqSpinlock so fault-handler registration
  is safe). VmaSet::split_at + remove_range enable partial munmap.
  Truncate walks a per-inode mappers reverse-map and unmaps invalidated
  PTEs across every live mapper process with per-process TLB shootdown.
  Past-EOF access kills the faulting thread (code 11). sys_msync (SYS=34),
  and OpenOptions.read/write carry the access mode in the low two bits of
  the open flags. 7-test userspace
  mmaptest (MAP_PRIVATE read, COW write, MAP_SHARED + msync, two-mapper
  visibility, past-EOF kill in forked child, truncate invalidation kill,
  fsync+msync round-trip) all pass on EFS. Side win: fixed a latent
  map_address bug where read-only user mappings created PML2 entries without
  WRITABLE, poisoning the 2 MiB range for later writable mappings (was
  causing wm to crash after 30s of SHM cycling); debug_assert_permissive
  _parents catches regressions.
- **ElfSegment -> FileBacked migration (2026-04-12)** - ELF loader no
  longer keeps the binary as Arc<Vec<u8>>. load_elf takes Arc<VfsInode>
  + Path; per-PT_LOAD it builds VmaBacking::FileBacked { inode,
  file_offset, shared:false, writable_mapping, pages } reusing the
  per-inode page cache, plus a separate Anonymous VMA for the BSS tail
  past the last file page. Partial last file page is eagerly zero-padded.
  Bulk-prefetch via prefetch_file_pages still feeds the eager-reloc pass
  (writable .data pages COW-materialize at load time because RELATIVE
  entries are patched in place; .text/.rodata stay shared via the cache).
  Thread::new_user threads the inode through; FileBacked VMAs register on
  inode.mappers for truncate invalidation. VmaBacking::ElfSegment,
  load_elf_from_bytes, FaultSource::ElfData and their fault/free arms all
  deleted. Wins: page-cache reuse across re-exec, sharing across fork, no
  per-process full-binary copy. Prerequisite for the dynamic linker.
- **Arc/Weak thread handles (Foundation #1, 2026-04-16)** - Replaced
  raw TID storage in every sync primitive and IRQ-reachable static with
  `Weak<Thread>`. `Scheduler::wake_thread` / `wake_thread_irq` now take
  `&Weak<Thread>` exclusively (TID-based wake API deleted). Migrated:
  WaitQueue, PollWaiter, broadcast Subscriber, AHCI slot_waiters,
  ThreadExitRegistry waiters, AHCI/xHCI/e1000e/HDA/keyboard/mouse driver
  dispatcher handles, REAPER_HANDLE, kill_process. Dangling Weak →
  silent no-op wake instead of waking a TID-recycled successor. Closes
  the latent "wake wrong thread" race; prereq for Foundation #2
  (cancellable waits) and async NCQ readahead.
- **Cancellable waits + deferred VfsInode eviction (Foundation #2, 2026-04-17)** -
  `VfsInode::drop` posts orphan-inode evictions to a dedicated evict-inode
  kthread instead of calling `fs.evict_inode` inline (which issues AHCI
  I/O). Per-`Thread` `owned_ops: IrqSpinlock<Vec<Arc<dyn CancellableOp>>>`
  registry drained at the top of `Thread::free`. AHCI command slots
  (`[Option<Arc<AhciSlotOp>>; 32]`) register ops so dying threads don't
  leak slots. USB mailbox audit: existing Arc<ResponseInner> semantics +
  Foundation-#1 silent wakes mean no CancellableOp needed. Drop-contract
  runtime guards (debug_assertions) catch blocking Drops fired from
  reaper/evict-kthread context. `/proc/evict_stats` + userspace
  `evicttest` program verify the pipeline end-to-end. Along the way:
  root-caused an edos_rt `FileDesc` Drop bug that made every Rust
  program leak fds (now fixed in edos_rt + Rust std fork).
- **Physical frame RAII for CachedPage (Foundation #3, 2026-04-17)** -
  `CachedPage::drop` deallocates the frame on last Arc drop. Removed
  manual `deallocate_frame` in `get_or_fill`'s race path and the
  `strong_count == 1` heuristic in `invalidate_from`. Fixed a
  pre-existing pin leak in `store_cached_page_on_vma` surfaced by the
  new Drop's pin_count==0 assertion.
- **Per-inode async I/O registry (Foundation #5, 2026-04-17)** -
  `InodePages.in_flight: IrqSpinlock<BTreeMap<u64, Arc<PageFillHandle>>>`
  at lock rank 42. `PageFillHandle` carries Weak<VfsInode>, page range,
  WaitQueue, AtomicU8 state (PENDING/SUCCESS/FAILED) and a CancellableOp
  impl so issuer death doesn't strand waiters. Reader state machine in
  `get_or_fill_async_sync` / `get_or_fill_bulk_async_sync`: fast (cached)
  -> slow (join existing handle, park on waitqueue) -> publisher (install
  handle, run fill_fn without InodePages locks held, publish pages(40),
  finish_state, remove from in_flight(42)). Invariant: terminal state
  MUST be published before the handle is removed, else a waiter can
  wake to an empty map and miss the wake. Bulk fills share one handle
  across [start, start+count). Replaces the legacy `InodePages::get_or_fill`
  (deleted). /proc/inflight_stats (installs/joins/retries/cancels/current)
  and programs/inflighttest verify the pipeline. Bugs caught in-session:
  orphan waiters on !push_ok (fixed), u32 truncation on bulk len
  (widened to u64), and a pre-existing ring-0 demand fault with IRQs
  disabled in idt.rs exposed by the new concurrency.

### The shell, 2026-08-10

- **Real type.** `edos_render` rasterizes outlines through `fontdue` with a
  glyph cache: Lato for chrome, JetBrains Mono for the terminal and editor,
  loaded from `/share/fonts` with the bitmap face as the fallback. One scale,
  12/14/15. Text is measured, not counted, so buttons size to their labels and
  the panel truncates titles by pixels.
- **A panel with regions.** Launcher, centred task list, status area, all with
  icons from a new `edos_render::icons`. Task buttons size to content between
  96 and 200px.
- **An applications menu**, owned by the panel process as a second window, with
  shut down, restart and halt on the existing `reboot` syscall. It needed
  `FLAG_DOCK` split into `FLAG_UNDECORATED` and `FLAG_NO_FOCUS`, since a menu
  is undecorated but must take focus to know when to close.
- **Minimize and maximize.** A window can be put away and brought back from the
  panel; before this the only way to clear one was to drag it off screen.
  Maximize fills the working area, not the screen, so the panel stays reachable.
- **A desktop menu** on right click: new terminal, widget demo, change
  background.
- **A disabled state** across Button, Checkbox, TextInput and Slider, and
  `HBoxLayout::set_uniform_columns` so rows of controls line up.
- **The kernel stopped knowing what a title bar is.** Each window carries the
  frame its manager gave it, through `property::FRAME`.
- **Windows are addressable by name.** `/proc/windows` publishes the kernel
  registry — id, pid, outer origin, client size, z-order, flags, frame and
  title — and the compositor copies that file into the kernel log on
  `Ctrl+Alt+W`, which is how the geometry reaches a host driving a headless
  guest. `scripts/edos-vm windows` and `scripts/edos-vm focus <title>` are the
  host side; `focus` clicks a point of the target that nothing above it covers,
  so it raises a partly hidden window instead of focusing whatever is on top.
- **Wallpapers.** `edos_render::image` decodes 24- and 32-bit BMP and scales an
  image to cover the screen, and the compositor cycles the generated lit grounds
  and every readable `.bmp` in `/share/wallpapers` through the same desktop-menu
  entry. The shipped one is generated by `scripts/mkwallpaper.py` at build time,
  since this repo holds no binaries.
- **The status area does something.** The volume button opens a slider that
  drives the HDA output amps through two new `/dev/dsp` ioctls (the gain scale
  comes from the codec's own amp capabilities, and zero mutes rather than
  attenuating); the network button reports link, address, gateway, resolver and
  MAC, read from a new `/proc/net` rather than parsed out of `SYS_NETINFO`,
  which renders the same state with ANSI colour for a terminal.
- **`std` reaches the whole syscall table.** `edos_rt` 0.0.42 and the shims on
  `edos_std_v3` close the nineteen syscalls the fork had never been moved for:
  symlinks, file times, vectored I/O, `nanosleep`, streaming `ReadDir`, `access`
  behind `try_exists`, and `openat` so an open no longer allocates a `CString`.
  `File::set_times` needed the kernel to grow POSIX `futimens`: a null path now
  means the file the descriptor names.
- **The USB HID driver reads report descriptors.** It bound devices on the
  interface protocol code and decoded one hard-coded layout, so it understood
  exactly two devices: a boot keyboard and a boot mouse. Every HID interface's
  report descriptor is now parsed (`drivers/usb/hid/report.rs`) into a field
  map carrying bit offset, width, signedness, usage and -- the bit that cannot
  be guessed from a byte layout -- whether an axis is a position or a
  displacement. A pointer is bound because it says it has X and Y, not because
  of a protocol code, which is what lets `usb-tablet` in: it declares no boot
  interface and had been enumerating and being dropped. `mouse::apply_absolute_move`
  stores the position instead of accumulating into it, and the boot decoder
  stays as the fallback for a descriptor that will not parse. `scripts/edos-vm`
  names a pixel in one event now instead of homing into a corner and counting
  relative steps, and a VNC client's pointer stays with the guest cursor.
- **A window-manager privilege.** Moving, resizing, framing, minimizing and
  posting events to a window you do not own were ungated: any process could do
  any of them to any window. They now need the shell privilege, which init
  holds by being the process the kernel starts and hands to the compositor and
  the panel per spawn. It dies with the process, so a reused pid inherits
  nothing, and it follows a process's threads because this kernel has no
  thread-group id. `wintest` carries the negative control.

### Sessions of 2026-08-08 to 2026-08-10

Mechanism kept because it is not recoverable from the diff. Verified in a
booted guest unless a line says otherwise.

- **User VA is reused.** `find_free_address` is a first fit over the VMA
  tree searching from the base every time. Mapping stride fell from
  ~940 MB to 8-10 MB, and successive mmap/munmap cycles return the same
  address.
- **`sys_window_list` no longer holds a spin guard across a user copy.**
  3000 soak rounds and 207k registry acquisitions with no stuck reader.
- **Filesystem errors keep their errno** instead of being flattened to
  EINVAL; missing paths report ENOENT.
- **`make filesystem` creates the directories it claims to.** It relied
  on brace expansion, which dash does not do, so `/var` never existed.
- **`OpenOptions` actually opens files for writing.** `read`, `write`,
  `truncate` and `create_new` were no-op stubs in the std fork, so every
  file opened read-only as far as the kernel was concerned. mmaptest went
  from failing at test 3 to all 10 passing on `/var` and `/tmp`.
- `sha256sum` and `file` (Phase 3 userspace).

- **The window-registry hang is root-caused and fixed.** The holder was
  never parked; it was Ready and starved. The scheduler armed a
  timeslice it never enforced, and its anti-starvation path only
  covered wake-boosted threads, so a priority-10 kthread spinning on a
  lock held by a priority-7 thread deadlocked outright. Both fixed,
  with `starvation-victim` in sched_test as the regression test. This
  bounded every spin lock in the kernel, not just the window registry.
- **`make test` is green (31/31)**, having been red on trunk: the
  abort-race test was a bare `thread_park_while` caller.
- **Spin locks shared between threads now suppress preemption**
  (`thread/preempt.rs`: per-CPU counter honoured by `maybe_preempt`,
  plus PreemptSpinlock/PreemptRwLock). Converted VFS, vmas,
  memory_manager, shared memory, the thread registries and the window
  locks. Preemption rather than interrupts, because vmas and mm are
  held across tree and page-table walks. The park primitives
  debug-assert preemption is enabled, which audits the whole class.
- **VfsInode::drop no longer panics on the reaper.** The drop-contract
  guard asserted "never runs here" when the contract is "never blocks",
  and the reaper releasing an orphaned inode is exactly the case the
  evict kthread exists for. mmaptest's unlink-while-mapped test
  panicked the kernel on trunk; now 10/10 on /var and /tmp.

- **The userspace allocator no longer fragments without bound.** The WM's
  metronomic 64 KiB-per-9.2s heap growth was `edos_rt`'s `PoolAllocator`
  never coalescing. Fixed in 0.0.36 (details above), which also carried
  the std fork's pin forward ten releases from 0.0.26.
- **`edos_rt` 0.0.37: the rest of the runtime.** Reading the crate after
  the allocator fix turned up more than the fragmentation did. The
  syscall wrappers were `no_mangle extern "C"`, so every syscall paid an
  out-of-line call plus a shuffle from the C argument registers into the
  kernel's, and the exported symbols were what forced `edos_lib` and four
  programs to hand-roll their own copies; they are inline Rust functions
  now, which is sound because the kernel's entry stub restores every
  argument register. `thread_join` asked for a non-blocking `waitpid` and
  slept 1 ms in a loop, so every `JoinHandle::join` polled at 1 kHz.
  `getrandom` returned a count that std's `fill_bytes` discarded, so a
  short read left the tail of the buffer holding whatever was there
  before. `IoError` folded every errno but three into `Unknown`, which is
  why errors displayed as "uncategorized" no matter what
  `decode_error_kind` mapped. The allocator now unmaps idle chunks
  instead of only plateauing, honours alignment above a page on large
  allocations (`mmap` alone returned them 4 KiB out), and caches freed
  large mappings within a 4 MiB bound. 0.0.38 then put the
  allocator back on a spin lock (parking under a list walk bought
  nothing) and stopped the inlined syscall wrappers promising that
  argument registers survive a park.

  Chasing corruption under eight allocating threads through the allocator
  was a wrong turn twice over: the cause is in this repo. Concurrent
  `mmap` hands the same address to several threads, because `sys_mmap`
  picks the range under one acquisition of the VMA lock and inserts the
  VMA under another. See doc/WORKING-NOTES.md.

- **Per-operation logging is off by default.** The kernel logged a line
  per mmap, munmap, spawn, ELF load and thread exit: a String allocation
  on the calling thread, and a byte-at-a-time UART write under a global
  lock on the drain side, one VM exit per byte under KVM. `log_debug!`
  checks a relaxed atomic before formatting, so a disabled site costs one
  load and nothing else. `loglevel=debug` on the kernel command line
  brings them back without a rebuild. Six threadtest+hammer iterations
  went from dozens of lines each to zero.
- **`decode_error_kind` in the std fork is no longer five errnos.** The
  mapping lives in `library/std/src/sys/pal/edos/common.rs` and covers 20.
  The old entry here claiming five was stale.

- **Unvalidated addresses no longer reach a VMA insert.** The audit found
  the ELF loader building a mapping out of `base_addr + p_vaddr` with no
  bound on it. `sys_mmap` turned out to be the shorter path to the same
  insert: `mmap(0x0000_9000_0000_0000, 4096)` from any program panicked
  the kernel in `VirtAddr::new`, reproduced on the pre-fix kernel before
  fixing it. The bound lives in `VmaSet::insert` now, so every caller
  inherits it, with `insert_validated` for the paths handing back a range
  they already held. `find_free_address` had the same shape of bug in its
  align-up, which wrapped for a length near `u64::MAX`. mmaptest test 11
  is the regression test; 11/11 on EFS and memfs.

- **CPU affinity is enforced now, at the three points where a thread is
  placed: spawn, wake and steal.** `thread_can_run_here` was stubbed to
  `true` and `complete_wake` used the waker's CPU regardless, so a pin
  held only until something woke the thread. `spawn_thread` was worse
  than unenforced: its else-arm claimed another CPU would queue the
  thread and nothing did, so un-stubbing the check without fixing it
  would have lost threads. sched-test grew affinity-pinned and
  affinity-waker (49 tests); the wake rounds are the part that fails
  when the check is reverted.

- **The audit's second half is done.** `clock_gettime` answers from the
  monotonic counter with a real epoch (and `read_rtc` now retries until
  two reads agree, since one torn read at boot would be permanent);
  path-taking syscalls fill a stack buffer instead of allocating;
  `pread`/`pwrite` and `getuid`/`getgid` exist; the five bare
  `spin::Mutex` sites are preempt-safe; TCP has an RFC 6298 retransmit
  timeout; `fs/api.rs` returns an error instead of panicking. New
  programs `iotest` and `tcptest` cover the new syscalls.

  Two audit recommendations were checked and **not** implemented,
  because their premises are wrong. CLOEXEC has nothing to govern:
  there is no `exec`, `spawn` hands the child exactly three
  descriptors, and no `O_NONBLOCK` exists to set. `setuid` without a
  permission model would be a privilege change that enforces nothing.

  `iotest`'s eight-thread positional read found a real bug on the way:
  `sys_read` took the fd-table BlockingMutex with interrupts disabled,
  which starved a TLB shootdown into its timeout. Fixed.

  `tcptest` found a bigger one, still open: no TCP connection can be
  established at all, because the guest RSTs the SYN-ACK. It predates
  this session. See doc/bugs/2026-08-08-tcp-connect-rsts-its-own-synack.md.

- **`execve` exists**, with `fcntl`/`FD_CLOEXEC`. The audit's CLOEXEC
  item was rejected earlier for having nothing to govern; exec is what
  gives it something. Along the way: `Thread::new_user` split into an
  image loader and a thread attacher, the address-space teardown made
  reusable, and `killed` finally observed at the syscall boundary rather
  than only in a PTY read. `exectest` covers it, including exec from a
  multithreaded process, which is the case that found the quiesce bug.

- **There is an init process.** `bin/edos-init` is the only thing the
  kernel starts; it supervises the three GUI services and restarts them,
  and a failed boot-load logs instead of panicking the kernel. Threads
  carry a parent now, which fixed an unbounded leak of exit statuses
  (nothing could ever collect a status whose waiter had died) and gives
  orphans somewhere to go. Killing the WM restarts it and the desktop
  survives.

- **A port restart no longer strands the op it meant to fail.** The AHCI
  watchdog entry here proposed gating `enter_ncq_mode` on `restarting`;
  that gate keeps new submitters out, and the op that strands is already
  past it. Publishing `reset_generation` before the fail-all pass, and
  re-reading it in the submitter after `issued`, is what closes it. Forced
  restarts under load: 1 stranded in 33 before, 0 in 106 after.

- **`http` and `wget` work.** They used `std::net::TcpStream`, which the
  std fork does not implement, so both failed at connect whatever the
  kernel did. `edos_lib::http` now carries the client the two shared, over
  `edos_lib::net`. A 300000-byte file arrives byte-identical to the host's
  copy. `dns_resolve` reports why a lookup failed instead of calling every
  failure "no A record", and its answer walker no longer desynchronises on
  a name that ends in a compression pointer after its labels.

- **A mapping owns every page it touches.** `VmaSet::reserve` searched for
  a page-rounded gap and recorded the VMA with the raw length, so mappings
  whose length was not a page multiple shared a page with their
  neighbour, and a zero-fill fault or an unmap on either one destroyed the
  other. Any `Vec` grown past 64 KiB came back zeroed with its length
  intact. First fit is what made it reachable: the old bump allocator was
  page-aligned by construction. `vectest` is the regression test and
  `doc/bugs/2026-08-08-mappings-sharing-a-page.md` the writeup.

- **The cwd mutex is no longer taken with interrupts off.**
  `info.lock().cwd.lock()` held the per-thread IrqSpinlock guard across the
  `BlockingMutex` acquisition at eighteen call sites, which panicked the
  kernel at boot and then wedged a second CPU behind the dead one's
  unanswered TLB shootdown IPIs.

- **TCP works.** `WaitQueue::wait_until_timeout` slept once and returned
  on any wake, so connect's five-second wait for Established ended in
  microseconds, tore the connection down, and RST'd the SYN-ACK that
  arrived just after. No connection had ever been established. The timed
  wait honours its deadline now, and sys_read's socket paths loop on
  their own condition instead of reporting EOF on an empty buffer.
  Verified with a 270 KB HTTP response; ping also stopped losing its
  first packet. The RFC 6298 RTO from earlier is finally exercised.

- **A kill reaches a thread that makes no syscalls.** The syscall return
  boundary covered every real program but not one spinning in user code,
  which is why `execve` had to bound its sibling quiesce and refuse with
  EAGAIN. The timer tick now checks the same flag when the frame it
  interrupted is ring 3, which is the proof the thread holds no guard —
  there is no unwinding, so dying anywhere else leaks whatever it held.
  `programs/killtest` covers both boundaries and `exectest` test 5 covers
  exec with user-spinning siblings; both fail on the previous kernel and
  the other four exectest cases do not.

- **`shutdown` stops the machine properly.** `reboot(cmd)` (syscall
  169, cmd 0 power off / 1 reset / 2 halt) syncs every filesystem, then
  drives ACPI soft-off: PM1a_CNT comes from the FADT and SLP_TYPa is
  decoded out of the DSDT's `\_S5_` package, with the emulator ports as
  a fallback and `RST_CNT`/8042 for the reset. `programs/shutdown` is
  the command. A guest stopped this way leaves a clean journal, so
  `efs-fsck` runs its dir-tree pass without a `--repair` replay first.

- **The audit's syscall table is closed.** `access`, `nanosleep`, path
  `truncate`, `utimensat`, `symlink`/`readlink`, `sigprocmask`,

## Boot Race / Heap Expansion Bug (fixed)

All fixes implemented:
1. **Lazy vmalloc fault handler** -- page fault handler walks kernel PML4
   lock-free for faults in KERNEL_HEAP..VMALLOC_END. If mapping exists,
   invlpg and retry. Handles stale paging-structure cache entries.
2. **Heap expansion serialization** -- AtomicBool EXPANDING ensures only
   one CPU expands at a time. Waiters spin then retry.
3. **Per-CPU heap freelists** -- 6 size classes (32-1024 bytes), 16 slots
   per CPU. Most small allocations avoid the global heap lock. Batch
   refill/drain of 8 objects. FSGSBASE enabled for fast per-CPU access.
1. **TLB flush fix** -- switch_to_kernel_page() no longer calls
   tlb_flush_all_including_global() unconditionally. Cr3::write
   already flushes non-global entries. The unconditional global flush
   was the root trigger for the intermittent boot hang.
2. **Page fault off IST** -- Page fault handler uses the kernel stack
   instead of IST 1. Nested page faults (vmalloc fault during demand
   fault handling) work naturally. Double fault retains its own IST
   for stack overflow protection.

TLB shootdown IPIs also implemented for safe page unmapping on SMP
(deferred frame free in munmap, shootdown in COW fork).

The 512KB heap warmup workaround was removed. 20/20 boot passes
(was ~1 in 5 failure rate).

## Open questions / loose ends

### Transient boot GPF — ROOT-CAUSED 2026-04-15 (frame allocator aliasing)
Earlier "transient boot GPF" in `IntrusiveList::push_back` with a
non-canonical head/tail was a secondary symptom of a bigger bug:
the physical frame allocator was handing out the same phys frame
twice (heap ↔ vmalloc DMA). virtio-gpu DMA response data was
overwriting scheduler runqueue memory, producing the non-canonical
pointer.

Root cause: `MemoryManager::map_address` / `map_address_range` set
the bitmap bit for the target phys but did not bump the refcount.
`unmap_memory`'s `deallocate_frame` later decremented a refcount
that was never incremented — when the phys was ALSO held by a
heap mapping (refcount=1 from `allocate_frame`), the decrement
took it to 0, cleared the bitmap bit, and the next allocation
returned that still-mapped frame.

Fix: `map_address` now calls `inc_or_set_refcount` instead of
`set_frame_allocated`. Each mapping holds a real refcount; the
final unmap drops to 0 and clears the bit.

Regression guard: `memory::verify_kernel_no_phys_aliasing()` runs
at the end of `init_drivers()` and panics if any kernel-half phys
is mapped at two virts. Also a hard `assert!` in
`BitmapFrameAllocator::deallocate_frame` catches refcount-0 double
free. The intrusive-list canonical-address debug_assert stays as
defense in depth.

### Warm spawn latency regression after inode_cache removal
Removing `EfsDriver::inode_cache` was correct design (one cache,
not two) but warm `/bin/ps` load went from ~0.2ms (pre-block-cache,
BTreeMap hit) to ~6ms (block page cache lookup + inode parse). Not
urgent — 6ms is fine absolutely — but if warm spawn latency
matters later, add a tiny CPU-local inode parse cache (say 8
entries, FIFO) in EFS to avoid re-parsing the same inode on every
open.

### FAT32 full-cluster write vs RMW
Aligned full-page writes now skip RMW. Cluster writes that are
smaller than a page (e.g. 512B sector with cluster_size=1) still
RMW. Fine for FAT32's small-sector case; document or optimize if
cluster_size starts mattering.

### Scheduler balance: parked-thread migration + wake-to-idle (not fixed)
Observed 2026-04-15 via `ps`: 13 kernel+user threads ended up parked
on CPU 3 while CPUs 0/1/2 each had 2 threads. The biased placement
traced to `pick_sched()`: sorted-lapic iteration + `>=` tie-break made
CPU 3 (last iterated) effectively never win ties, so early boot spawns
that all saw `thread_count=0` initially packed onto one CPU via a
different cascade. Fixed 2026-04-15 by switching `pick_sched` to a
rotating tie-break (`PICK_SCHED_ROTATION: AtomicU32` bumps each call),
so new spawns with equal counts round-robin across CPUs.

Not fixed: existing parked threads stay on their original CPU forever.
Work-stealing only moves Ready/Running. A driver kthread that parks on
CPU X stays on CPU X, gets enqueued back to CPU X's rq on wake. Two
follow-ups worth doing when scheduler load-balancing matters:

1. Let work-stealing steal parked threads too, OR a periodic rebalance
   pass that migrates parked threads from overloaded CPUs.
2. Wake-to-idle hint: when `wake_thread_handle` fires and the target
   thread's home CPU is loaded AND another CPU is idle, redirect the
   wake to the idle CPU's rq. Cleaner to do post-Foundation-#1 since
   the wake path already takes a `Weak<Thread>` handle.

### Driver kthread startup starvation on busy CPU
Observed 2026-04-15: mouse kthread can take up to 5 seconds to
start running because `pick_sched()` at spawn time placed it on the
same CPU as the e1000e driver kthread, which was blocked on DHCP
for ~5 seconds. Meanwhile `edos-wm` tried `open("/dev/mouse")`, got
`InvalidInput` (device not yet registered in devfs), panicked, and
exited.

Two issues conflate here:
1. Scheduler places cooperative-blocked-driver kthreads and
   latency-sensitive driver kthreads on the same CPU, starving the
   latter until the former unblocks.
2. Userspace programs assume their required `/dev/*` entries exist
   at program start. They don't (drivers register async).

The crash is no longer fatal to the session: `bin/edos-init` supervises
`edos-wm` and restarts it with backoff. That is a retry loop one level
up rather than a fix — `InputState::new` still `expect`s the open, so a
slow mouse kthread costs a restart cycle instead of a wait.

Fix options, ranked:
- (best) init should wait for `/dev/mouse` and `/dev/kbd` to exist
  before spawning `edos-wm` (and any program that depends on input).
  Possibly a generic "wait for device" syscall or a `/dev/.ready`
  sentinel.
- edos-wm retries `open("/dev/mouse")` with backoff in-process instead
  of dying and being respawned.
- `queue_spawn_kthread_named_on(cpu)` variant so mouse and keyboard
  go to specifically different CPUs from network drivers.
- Convert DHCP wait from `thread_park_while` on a 5s hard timeout
  to an event-driven kthread that yields between short polls.

## Ideas

### Foundations for async I/O (TOP PRIORITY, unblocks multiple features)

Discovered while planning async NCQ readahead
(`.claude/plans/async-ncq-readahead.md`): AHCI already supports
concurrent NCQ slots and IRQ-driven wake, but a split `submit/wait` API
is unsafe today because of generic kernel-infrastructure gaps. These
aren't "async is hard" issues — they are missing foundations that also
affect other planned work (proper SIGKILL delivery, process-level
cleanup on exec, multi-threaded file I/O, virtio-blk / USB async reads,
reaper correctness in general). Roadmap in dependency order:

1. **Thread handles with Arc / Weak refcounting instead of raw TIDs.**
   **DONE 2026-04-16.** `Scheduler::wake_thread` / `wake_thread_irq`
   now take `&Weak<Thread>` exclusively; the TID-based API is deleted.
   Every sync primitive (WaitQueue, PollWaiter, Subscriber, AHCI
   slot_waiters, ThreadExitRegistry waiters, every driver dispatcher
   thread handle, REAPER_HANDLE, kill_process) stores `Weak<Thread>`.
   A dangling Weak upgrades to `None` → `wake_thread*` is a silent
   no-op instead of waking a recycled TID's successor. See CLAUDE.md
   "Thread handles" invariant and `.claude/plans/arc-weak-thread-handles.md`.

2. **Cancellable / transferable waits for dying threads.** When a
   thread is killed (SIGKILL, process group termination) while parked
   on I/O, the reaper needs a way to hand off ownership of the
   pending resource (kernel cleanup thread, destination page cache).
   Today the reaper just drops the stack, so anything with a blocking
   Drop deadlocks the reaper. Pieces: a "cleanup queue" the reaper
   drains, `Drop` contracts that never block, per-thread list of
   owned async resources. Prereq for real signal handling too.

3. **Physical frame RAII for cache pages.** **DONE 2026-04-17.**
   `CachedPage::drop` deallocates the frame on last Arc drop (mirrors
   `CachedBlockPage::drop`). Removed the manual `deallocate_frame` in
   `InodePages::get_or_fill`'s race-insert path and the
   `strong_count == 1` heuristic in `invalidate_from`. Debug assert on
   `pin_count == 0` at drop caught a pre-existing pin leak in
   `store_cached_page_on_vma` (fixed: unpin at entry).

4. **Strict lock-order discipline for fs/page-cache paths.**
   **DONE 2026-04-17.** Canonical rank table in
   `doc/invariants/lock-order.md` (ranks 10-200 for subsystem locks;
   900/910 for deep utility leaves kernel_mapper/frame_alloc).
   Per-thread rank stack (`Thread.lock_ranks`, `heapless::Vec`, debug
   only) enforced by `ranked_lock!` / `ranked_read!` / `ranked_write!`
   macros and `RankedGuard<G>` (ManuallyDrop-based RAII). All ~80
   ranked lock sites across VFS, page-cache, journal, EFS, AHCI, frame
   allocator, and memory manager instrumented. `/proc/lock_order_stats`
   exposes inversion count + max stack depth. `lockordertest` program
   verifies inversions==0 after a representative workload.

   **Caught 6 pre-existing latent lock-order bugs in one session:**
   (1) journal `tracker->state` AB/BA via `committed_seq()` under
       `checkpoint_tracker` in `is_safe_to_flush`/`advance_tail`;
   (2) thread-teardown `mm(80)->vmas(70)` in TLS cleanup + last-thread
       VMA teardown, narrowed by drop-reacquire;
   (3) EFS `mutable(160)->BPC(110)` in `alloc_inode`/`alloc_block`,
       fixed by adding `alloc_mutex(32)` serializer and narrowing
       `mutable` scope out of BPC I/O (**side-effect perf win**:
       mmaptest full suite dropped to ~200ms — mutable no longer held
       across AHCI reads);
   (4) BPC `shard(110)->frame_alloc(90)` via `CachedBlockPage::drop`
       during eviction, fixed by deferring Arc drops out of shard scope;
   (5) VFS `inode(30)->VFS(10)` in `list_files` calling
       `child_mount_points` under inode guard, narrowed guard to the
       FS driver call;
   (6) BPC `write_lock(140)->kernel_mapper(85)` via AHCI DMA
       translation during writeback — fixed by moving kernel_mapper
       and frame_alloc to deep-leaf ranks (900/910). **Systemic
       lesson**: utility leaves called from arbitrary contexts must be
       numerically HIGHEST in the rank table, not near their
       call-site neighbors.

   Each rank-fix was also a lock-hold-time shrink (overbroad locks
   get caught because they're held across paths that reach lower
   ranks). The tracker doubles as a "lock-hold-time linter". See
   `.claude/plans/foundation-4-lock-order.md` and the session handoff
   at `.claude/handoff/2026-04-17-2-foundation-4-complete.md`.

5. **Per-inode async I/O registry (last layer, uses #1-#4).**
   **DONE 2026-04-17.** `InodePages.in_flight` at rank 42 +
   `PageFillHandle` (`fs/page_fill.rs`) + `get_or_fill_async_sync` /
   `get_or_fill_bulk_async_sync` reader state machine + `/proc/inflight_stats`
   + `programs/inflighttest`. Replaces the legacy synchronous
   `InodePages::get_or_fill` (deleted). Publish-terminal-state-before-remove
   invariant enforced in the free fn; handle registered as a per-thread
   `owned_op` so reaper cancels dying-issuer fills. See
   `doc/bugs/2026-04-17-foundation-5.md` and
   `.claude/handoff/2026-04-17-3-foundation-5-phase-4-plus-ahci-ncq-hang.md`.

3. **Generic async block I/O trait. DONE 2026-05-19.** `AsyncBlockDevice`
   with AHCI callers migrated (Phase A, `04232c0`), USB MSC migrated and
   BPC dispatch collapsed (Phase B, `35ad890`). AHCI NCQ submit/complete
   split with an IRQ-driven dispatcher (Phase C1, `cf7938e`, fixed in
   `83a5117`), async readahead via lazy finalization by the first joiner
   (Phase C2, `83ddde9`), NCQ watchdog kthread (`22727bc`) and its
   counters in `/proc/ahci_stats` (`c5455d1`).

#1-#6 are all shipped. The foundations roadmap is closed.

Residual from #6, now closed: a port restart could leave pending the very
op it meant to fail. `fail_all_ncq_slots` skips a slot whose `issued` is
still false, and `reset_generation` was bumped at the *end* of
`restart_port`, after that pass; a submitter that stored `issued` in
between and sampled `SACT` before the reset cleared it saw an unchanged
generation and a set bit, so it returned and waited for a completion
nobody would deliver. The next watchdog sweep found it up to 30s later.

The gate this entry used to propose is not what fixes that. Gating
`enter_ncq_mode` on `restarting` keeps *new* submitters out; the one that
strands is already past the gate when the reset begins. The fix is
ordering: publish the generation before the fail-all pass, and have the
submitter re-read it after storing `issued`, so the two cover each other.
The gate went in anyway, as a throughput measure.

Validated rather than argued, since it touches the storage submit path.
`ahci_ncq_timeout_ms=0` on the kernel command line makes the watchdog
treat every in-flight op as hung, which is the only way to land resets
inside submits at any useful rate — a real NCQ command against a backing
file completes in well under a millisecond, so no sane positive timeout is
ever reached. `/proc/ahci_stats` gained `stranded`, counting ops a sweep
finds still pending from an earlier generation, which is the bug's exact
fingerprint. Under forced restarts with mixed read/write load: 1 stranded
in 33 restarts before the fix, 0 in 106 after.

Note: the `.claude/plans/*.md` and `.claude/handoff/*.md` paths cited
throughout this file are gone — that directory is not in the repo.
Treat the prose here as the record, not those links.

### Extend lock-order ranks to more subsystems (Foundation #4 follow-up)

Foundation #4 shipped rank instrumentation across VFS, page-cache,
journal, EFS, AHCI, frame allocator, and memory manager. The mechanism
(`ranked_lock!` + `Thread.lock_ranks` + per-thread rank stack) is
generic and applies to any `Mutex`/`RwLock`/`IrqSpinlock` in the
kernel. In the fs/mm audit it caught 3 real pre-existing inversions in
its first boot cycle (journal `tracker->state`, thread teardown
`mm->vmas`, EFS `mutable->BPC`). Extending to other subsystems is a
high-ROI way to shake out latent inversions before they manifest as
rare concurrent-load hangs. Candidates, ranked by fun-per-effort:

1. **Networking stack — DONE 2026-08-09.** Ranked `NET_STACK` 240,
   `PORT_TABLE` 250, `Socket` 260, `TcpConnection` 270, in the order the
   receive path fixes. Yield: two pre-existing AB/BA inversions, both
   taking the port table while holding something that belongs inside it
   (`tcp_retransmit_main` cleanup under a connection guard, and
   `close_descriptor` under a socket guard). Both sat between a syscall
   and a driver kthread that run concurrently, and neither is visible by
   reading either function alone. Details in
   `doc/invariants/lock-order.md`. Route table and ARP cache live inside
   `NetStack` and need no separate rank.
2. **USB stack — DONE 2026-08-10.** No locks to rank inside it: the
   `XhciController` is reached only as `&mut self` from its driver
   thread, and every other thread goes through a channel. The ranks the
   sweep added are the channels themselves — `Mailbox.queue` 204 and
   `ResponseInner.value` 206 (USB block I/O and FS mount requests),
   `Broadcaster.subs` 310, and the `/dev/kbd` + `/dev/mouse` poller
   lists 320. No inversions. Two real fixes came out of it:
   `Broadcaster.subs` was a bare `spin::RwLock` shared between kthreads
   and syscall context (now `PreemptRwLock`, and `subscribe` allocates
   its 256-slot queue before taking the guard), and the USB HID paths
   broadcast without notifying pollers, so `poll()` on `/dev/kbd` and
   `/dev/mouse` never fired with a USB device attached. Details in
   `doc/invariants/lock-order.md`.
3. **Window system — DONE 2026-08-09.** Ranked `WINDOW_REGISTRY` 280,
   `WINDOW_EVENTS` 290, `LAST_MOUSE_BUTTONS` 300. No inversions found:
   the registry is strictly outside, the input thread already drops its
   read guard before taking the write lock on a focus change, and
   nothing on the event-queue side reaches back into the registry. The
   read path is ranked inside `read_tracked`, which is the only way the
   registry is read, so every read site is covered by one call.
   `SHARED_MEMORY_REGISTRY` was left unranked here and got its rank from
   an mm-side analysis on 2026-08-10: rank 90, inside both address-space
   locks. The reason it could not be guessed from the window side is that
   the earlier "never co-held with vmas or mm" reading was wrong — it
   audited `syscalls/shm.rs` alone and missed `sys_fork`'s deep copy
   (under vmas 70) and `release_mappings` (under mm 80).
4. **HDA audio — DONE 2026-08-10.** One lock, not three: the whole
   driver (controller registers, BDL ring cursors, stream flag) sits
   behind `HdaPlaybackState`, rank 330. It was a bare `spin::Mutex`
   held across a memcpy loop into the DMA ring, shared between
   `/dev/dsp` writers and the HDA kthread; now a `PreemptSpinlock`.
   No inversions.
5. **devfs / PTY — DONE 2026-08-10.** `DevFs.shared` is rank 340,
   deliberately above every device lock it dispatches to, so a guard
   held across a driver callback panics instead of passing quietly.
   That caught a real one on the first `ls /dev`: `list_files` and
   `file_info` called `DeviceNode::file_entry` under the registry read
   guard, and `file_entry` reads `DevFsDevice::size`, which for
   `/dev/tty0` takes the rank-210 `BlockingMutex` — a spin lock held
   across a lock that can park. Both snapshot the nodes and build their
   entries after releasing the guard now. `TTY_POLLERS` also joined the
   device-poller class at 320 alongside the mouse and keyboard lists.

With that the list is finished; see "Every subsystem on the list is
ranked now" in `doc/invariants/lock-order.md`.

Marginal cost per subsystem: one rank constant, one row in
`doc/invariants/lock-order.md`, and s/`.lock()`/`.lock_ranked(RANK,
"site")`/ on ~10-30 sites. Per-subsystem cost a few hours; expected
payoff is a real bug or two per subsystem based on fs audit yield.

### Guards held across kill points leak (AUDITED AND FIXED, 2026-08-09)

**The evidence this entry was opened on was re-diagnosed.** A ~630s soak
deadlocked the GUI with all four CPUs spinning on
`spin::RwLock<WindowRegistry>::write` and the lock word reading `0x4`,
which was read as one leaked *reader*. The post-mortem concluded
otherwise: the holder was `Ready` and starved, not killed, and the fix
was in the scheduler. See
`doc/bugs/2026-08-08-window-registry-stuck-reader.md`.

So this class has never been caught in the act. It is kept, and was
swept, because the mechanism is real and provable by inspection rather
than because that hang was an instance of it.

`sys_window_list` held `WINDOW_REGISTRY.read()` across
`try_copy_to_user`. EDOS is `no_std` with no unwinding, so a thread
killed during that copy never runs `RwLockReadGuard::drop` and the
reader count is never decremented. `edos-wm` calls this every frame, so
the window was hit constantly.

Full writeup: `doc/bugs/2026-08-08-window-registry-stuck-reader.md`.

`sys_window_list` was the instance; the sweep for the rest found five
more, all of the same shape and all now fixed. The window is narrower
than "anywhere a thread dies": it is a guard live across a user copy.
`handle_demand_fault` runs *before* the uaccess fixup in the ring-0
branch of the page-fault handler and legitimately blocks (NCQ I/O,
block-page-cache contention, vma waitqueues), so a copy touching a
lazily-mapped or file-backed user page parks with interrupts on.

- `Pipe::write_from_user` / `read_to_user` copied under the
  `BlockingMutex<Pipe>` guard. Deleted; `sys_write`/`sys_read` buffer
  through `copy_in`/`copy_out` and call the plain `write`/`read`.
- `Pty::{master,slave}_{write_from_user,read_to_user}` did the same
  under `BlockingMutex<Pty>`. Now `master_write`/`master_read`/
  `slave_write`/`slave_read` take and return kernel buffers.
- `tty::write_from_user` held `TTY_BUFFER` across a chunked copy loop,
  which is stdout for every process. The lock is now taken per chunk.
- `vfs::read_to_user` held `inode.lock` (read) across the copy on the
  non-page-cache path — procfs and devfs reads. The bytes come out
  under the guard, the copy happens after it.
- `vfs::write_from_user` held `inode.lock` (write) across the copy on
  the same path. The buffer is filled before the lock is taken.

Checked and clean, because they already snapshot into owned memory
first: `sys_ioctl`, `sys_window_poll`, `sys_list_mounts`.

Still worth doing, and not covered by the above:

- Consider whether the reaper can do anything about guards at all.
  Today it frees the stack and destructors never run. A per-thread list
  of held ranked locks (`Thread.lock_ranks` already exists in debug
  builds) could at least *detect* a thread dying with locks held. That
  is the guard against this class regressing, since nothing about the
  fixes above is enforced by the compiler.
- This is the sibling of the drop contract: that one says drops must
  not block, this one says guards must not be live where a thread can
  die.

`lock_order::assert_no_guards_held`, called from `thread_exit`, is the
regression guard. Every path that ends a thread funnels through there,
so it is the one place the rule can be checked. The per-thread stack records
**ranked** locks only, so the three unranked ones the sweep touched were
ranked to make them visible: `TTY_BUFFER` 210, `Pipe` 220, `Pty` 230.
All six sites are now covered.

Where the rule can actually be broken today is narrower than "anywhere
a thread dies", which is worth writing down because it bounds the
search. Every ring-3 kill point — GPF, invalid opcode, alignment check,
page fault, the timer tick — interrupts user code, where the thread
provably holds nothing. `exit_if_killed` runs at the syscall return
boundary, after the body has returned and its guards are dropped. A
ring-0 uaccess fault takes the fixup and returns EFAULT rather than
killing. That leaves explicit `thread_exit()` calls inside syscall
bodies, of which there are two: `sys_exit`'s own (holds nothing) and
the pty slave read's SIGINT exit, which is checked at the top of the
loop before the guard is taken.

### Userspace allocator fragments without bound (FIXED, edos_rt 0.0.36)

Presents as "edos-wm leaks heap": on a fully idle desktop the WM grows
its heap by 64 KiB every 9.2 seconds, metronomically, and never gives
any back. 24 consecutive growths at 9.18-9.30s spacing during a window
with no input and no process churn, zero munmaps in the whole log.

It is not a WM bug. The 64 KiB matches `CHUNK_SIZE` in `edos_rt`'s
`PoolAllocator`, and that allocator has three compounding defects:

1. **No coalescing.** `add_to_free_list` pushes blocks onto a singly
   linked list and `split` carves them up, but adjacent free blocks are
   never merged. Under a steady alloc/free workload the list shatters
   into fragments that individually satisfy nothing, so
   `allocate_new_chunk` grabs another 64 KiB. Growth is therefore
   proportional to allocation *rate*, not to retention, which is why the
   period is so exact.
2. **Sub-16-byte blocks are dropped.** `add_to_free_list` returns early
   when `size < size_of::<FreeBlock>()`, permanently losing the block.
3. **The tail of an exactly-fitting block is lost.** When `split` takes
   the "use entire block" branch it hands out a block larger than
   requested, but `dealloc` records `total_size` as the *requested*
   size, so the excess never returns to the list.

Any long-running program is affected; the WM is merely the busiest
allocator. It is the same reason the VA cursor advanced ~940 MB per
9.2s: every chunk was a fresh mapping.

**The fix was not a change to this repo.** `edos_rt` is a separate crate
published to crates.io and consumed through the Rust fork, so the loop
was: patch, bump, publish, update `library/std/Cargo.toml` in the fork,
rebuild the toolchain, rebuild programs.

Fixed in `edos_rt` 0.0.36. The free list is address-ordered and a
returned block absorbs whichever neighbours it touches; a merge cannot
join two chunks, because each chunk's usable region is preceded by the
chunk header inside the same mapping. Spans are rounded up to a
`FreeBlock` and to 8 bytes, so nothing untrackable is produced and
adjacent spans touch exactly. Chunks reserve the exact span and the
header records that span, so padding and tails come back on free.

Fragmentation also made allocation quadratic, since first fit walked an
ever-growing list. `bench/allocstress` in the `edos_rt` repo compiles the
allocator against a shimmed `mmap` on the host and asserts the pool
plateaus: a 200-allocation working set that mapped 22 MB in 41s over 200k
cycles now holds a flat 128 KiB in 21ms, unchanged at 2M cycles.

The std fork pin was ten releases behind (0.0.26), so this also brought
`msync`, file-backed `mmap` and the `OpenFlags` access-mode constants
into std for the first time.

### Async NCQ pipelined readahead (Foundations now shipped)

Linux's async-marker readahead: when the user reads the last page of
the current window, the kernel pre-fires the NEXT window's I/O so it
completes while the user consumes the current batch, keeping the I/O
pipeline full. Current EDOS readahead is sync-only, so steady-state
64 KiB user reads still trigger 64 KiB AHCI commands — the prefetch
window follows the user rather than pulling ahead. Small-file whole-
file prefetch (shipped 2026-04-15) covers files ≤ 2 MiB; async is
needed for the large-file case.

The Foundations this was blocked on are all shipped, and Phase C2
(`83ddde9`) landed async readahead via lazy finalization by the first
joiner. What remains is the pipelined async-marker behaviour proper:
firing the *next* window's I/O when the user reads the last page of the
current one, so the prefetch pulls ahead instead of following.

Payoff once Foundations + this land: first-run mmaptest test 10 on
/var EFS drops from ~500 ms (current, with whole-file prefetch) to
~150 ms; concurrent-read throughput improves across the board;
writeback/read overlap becomes possible.

### EFS write-path perf: batch journal tx per flush_dirty round (DONE 2026-04-15)
Shipped as commit `824e656`. Added `PageCacheOps::flush_pages_bulk`
with a default per-page loop; EFS overrides to chunk pages in 512-page
batches, each with one TxHandle and one `ensure_blocks_for_logical_batch`
(read inode once, walk all logical blocks with extent coalescing, write
inode once). Direct AHCI page writes bypass BlockPageCache. Also added
`InodePages::flush_dirty_bulk` with all-or-nothing semantics. vfs
`flush_file` and `flush_dirty_inodes` migrated. mmaptest test 7
(fsync+msync) on /var EFS: ~4.1s → 159ms (26x).

### EFS write-path perf: sequential-extent pre-allocation (up next after batching)
`flush_page` currently allocates one cluster at a time via
`ensure_block_for_logical`, which walks the extent tree per call and
splits what could have been one contiguous extent into many tiny
ones. For a growing file, we should detect the "append pattern" and
pre-allocate a contiguous extent of N blocks up front (maybe 32 or
64), then let subsequent `flush_page` calls land inside the already-
allocated range without walking/appending the extent tree. This
matches ext4's delayed allocation + multi-block allocator (mballoc).
Payoffs: fewer extent-tree entries on disk (less metadata to flush),
fewer bitmap updates (one BGD transaction per big alloc, not 480),
contiguous data on disk (faster reads later).

### Dynamic Linker (ld.so)
ELF dynamic linking: PT_INTERP, PT_DYNAMIC parsing, symbol resolution
(DT_HASH/DT_GNU_HASH), PLT/GOT lazy binding, dlopen/dlsym/dlclose.
Requires General Dynamic TLS model + DTV (dynamic thread vector).
Shared libraries share physical pages across processes via MAP_SHARED
file-backed mmap. Enables C library use, plugin systems, and shared
memory savings. Natural ordering: page cache -> file-backed mmap ->
dynamic linker.

### io_uring-style Async I/O
Shared-memory submission/completion ring between userspace and kernel.
Already have the SHM infrastructure. Very "modern OS" feature, unique among hobby OSes.

### IPv6
Full IPv6 support: different header format, NDP (replaces ARP), ICMPv6,
SLAAC/DHCPv6 for address configuration, multicast. Source-only fragmentation
(different model from IPv4). Not urgent since most targets work fine on v4,
but needed for a complete real-hardware network stack.

### GPU driver work (far future, no near-term plan)

The virtio-gpu driver we have is 2D only: dirty-rect transfers, blob
resources, hardware cursor. Two directions exist, and they teach
opposite halves of what a real GPU driver is. Neither is scheduled;
this is here so the options are written down rather than rediscovered.

**`ati-vga`, the hardware-facing half.** QEMU emulates a real ATI Rage
128 Pro / Radeon 9250 (`-device ati-vga,model=...`), with real MMIO
registers, a real 2D engine and a hardware cursor. The r100/r200
register documentation is public; it is what the classic `radeon` DRM
driver was built from. Bring-up would be authentic: PCI BAR probing,
MMIO programming, VRAM aperture setup, engine init, 2D blits, DMA.

The advantage over real silicon is that the device model *is* the spec.
`hw/display/ati.c` and `ati_2d.c` in the QEMU tree say exactly which
registers are implemented and what each does, so a hang is diffed
against the model rather than guessed at, and a `printf` can be added to
the model itself. The catch: it is hardware from 2003. No shaders, no
command processor, no GPU MMU.

**virtio-gpu 3D, the API-facing half.** Extending our existing
virtio-gpu driver past 2D means contexts, resource create/attach,
command-stream submission and fences, which is genuinely the object
model every modern DRM driver uses, and it builds on code we already
have.

Target the modern capsets rather than virgl. **Venus** (Vulkan) and
**native contexts** run a real Mesa driver in the guest and forward
actual hardware ioctls over the transport, so the guest side is doing
what a real driver does. Virgl is the older path: its command stream is
essentially serialised GL calls the host translates, which is further
from hardware and is not where the ecosystem went. QEMU exposes 3D
through the `-gl` device variants (`virtio-gpu-gl`, `virtio-vga-gl`),
which are compiled into the QEMU we run; the capset chosen on top of
that is what decides whether this is virgl or venus.

What the virtio path does *not* teach, and this is most of the
difficulty in a real driver: shader compilation to a hardware ISA, the
GPU's own MMU and page tables, firmware loading, engine scheduling and
preemption, clock and power management, and the VRAM/GTT hierarchy with
migration and eviction. Those live on the `ati-vga` side of the fence,
or on real silicon.

**Passthrough is not currently an option on the dev box.** VFIO would
need IOMMU enabled in firmware and on the kernel cmdline
(`/sys/kernel/iommu_groups` is empty today), and the only GPU is a
GeForce GT 710 driving the host display. A from-scratch Kepler driver
also means signed firmware for several engines; nouveau still cannot
reclock Kepler properly.

### virtio-net
Second NIC backend. Straightforward now that the stack and e1000e exist.
Useful for VMs where e1000e emulation is slower than paravirtual.

### SIGINT delivery to foreground processes — DONE (verified 2026-08-10)
Ctrl+C kills the foreground job. The chain works end to end and was
verified in the VM: `sleep 30` and a stdin-blocked `cat` both die on
Ctrl+C and the prompt returns, and Ctrl+C at an idle prompt leaves the
shell alive. Nothing was missing in the kernel — `LineAction::Interrupt`
already set `PtyNotifications::kill_pid` from the pty's `foreground_pid`
and `flush()` already called `kill_process`; the entry below was written
before that path was re-read.

What protects the shell is not the foreground bookkeeping: `edos-sh`
sets SIGINT to SIG_IGN at startup (`main.rs`, `sys_sigaction(2, 1)`) and
`kill_process_with_signal` returns early on SIG_IGN. Confirmed with a
negative control — a kernel that registers the session shell as the
foreground job unconditionally still leaves it alive.

That half is closed: the terminal tracks a foreground process *group*
(`Pty.foreground_pgid`), the shell puts every stage of a pipeline in one
group, and it takes the terminal back with `tcsetpgrp` after each job.

The "tools that read stdin hang with no way out" half of this is fixed:
Ctrl-D now ends the read. `Pty::slave_read` used to return an empty `Vec`
for both "Ctrl-D" and "nothing yet", so the caller could not tell EOF from
would-block and parked; it returns `PtySlaveRead::{Data,Eof,WouldBlock}`
now and `sys_read` breaks with 0 on `Eof`. Verified against a negative
control: with `Eof` folded back into no-data, `wc -l` hangs and the next
command is swallowed as stdin.

The userspace chain was never the problem and needs no work:
`edos_lib::keymap::map_keycode` already maps ctrl+a..z to 0x01..0x1a, the
terminal widget tracks the ctrl modifier, and the line discipline maps
0x04 to `LineAction::Eof` and 0x03 to `LineAction::Interrupt`.

### Non-ASCII keyboard input is double-UTF-8-encoded
Typing a non-ASCII key writes the wrong bytes. The `ç` key on the Spanish
ISO layout produces `c3 83 c2 a7` in a file rather than `c3 a7`: that is
`ç` encoded to UTF-8 once, then each of those two bytes reinterpreted as
a char and encoded again. Reproduce with `echo <ç> > /tmp/k.txt` then
`hexdump -C /tmp/k.txt`.

The terminal widget collects `Vec<char>` and `write_str`s a real UTF-8
`String`, and the PTY line discipline is byte-oriented and pushes bytes
through unchanged, so the doubling is above that — most likely a
byte-to-`char` cast on the shell's read or echo path. Worth fixing before
any more layout work: it makes every accented key untestable, and it is
why a wrong keycode mapping for `ç` went unnoticed until 2026-08-10.

### In-EDOS fsck (`/bin/fsck`)
Host `efs-fsck` is the canonical recovery tool. A thinner in-EDOS
userspace wrapper would be useful for unmounted secondary block
devices (USB drives, second SATA, attached image files). Cannot fsck
the live root FS without an initramfs (chicken-and-egg), and EDOS has
none — kernel still replays journal automatically on mount, which
covers the common boot case. Code reuse: `libs/efs-common` is already
`no_std` and works in userspace; the host crate's `std::fs::File`
calls would swap for `open("/dev/sdb")` + `pread`/`pwrite`/`fsync`.

**Prereq: done.** `/dev/sda`, `/dev/sdb`, `/dev/ram0` are block-device
nodes (`kernel/src/fs/devfs/block.rs`), byte-addressed through the block
page cache, with ioctls for flush, sector count, rescan and is-mounted.
`edos-install` already uses them, so an in-EDOS fsck has everything it
needs.

### Addressing the screen by name instead of by pixel (DONE)

Windows first: `/proc/windows` publishes the registry, the compositor
copies it into the kernel log on `Ctrl+Alt+W`, and `scripts/edos-vm`
grows `windows` and `focus <title>`.

The panel followed, by the same route rather than by the control daemon
first sketched here. Its buttons are not windows, so it publishes them
itself: the panel writes its controls to `/dev/klog` whenever its
layout moves and the applications menu writes its rows as it opens,
both tagged like the window dump. `scripts/edos-vm` grows `panel` and
`press <name>`, `launch` resolves rows by label, and no layout constant
is left in the script. `press <title>` also clicks a task button, which
is how a minimized window gets restored -- it has no on-screen geometry
of its own.

## What to do next (reviewed 2026-08-10)

Open, roughly in priority order. Items marked [audit] come from
doc/AUDIT.md, which has the file:line detail and the reasoning.

Hygiene and quality:

1. **`unwrap()`/`expect()` density in kernel code.** [audit] 204 across
   `kernel/src`, so recount rather than trusting the figure. Convert the
   ones on I/O and parsing results; leave a comment on the structurally
   impossible ones. The ELF loader (`loader/mod.rs`) is done. Next by
   count: `drivers/usb/xhci/mod.rs` (19), `fs/efs/mod.rs` (8),
   `drivers/ahci/port.rs` (8), `acpi/mod.rs` (7).
   The xhci ones are worth little on their own: 12 are `Option` fields
   that `init()` fills and the driver thread then uses, and removing
   them means making those fields non-optional, which means folding
   `init()` into `find_and_init()`. The rest are DMA-allocation
   `expect()`s on a `-> !` thread. Reading them did turn up a real
   defect (short control transfers parsed as descriptors), now fixed.
2. **Module READMEs for `fs/` (17.5k lines) and `drivers/` (13.6k).**
   [audit]

Still open from the audit, but deliberately unhurried. These are not
oversights; each has a reason it has not been done.

3. **TCP retransmit clones whole segments.** [audit 2.5]
   `resends.push(seg.data.clone())` copies the full segment per retry.
   This was theoretical while no connection could be established; now
   that TCP moves real data it is a live cost under loss. `Arc<[u8]>`
   and clone the handle.
4. **Scheduler quality, four items.** [audit 4] Load is measured as
   `thread_count`, so a sleeping thread weighs the same as a CPU-bound
   one and `pick_sched`/`try_rebalance` balance the wrong quantity.
   There is no priority inheritance, so a high-priority waiter still
   queues behind a low-priority lock holder. The timeslice is a flat 5ms
   regardless of priority. The idle loop polls for steals on a backoff
   instead of being told by an IPI.
5. **TLB shootdown is globally serialized.** [audit 2.6] One `active`
   flag and one request slot, so unrelated `munmap`s on different
   address spaces serialize. Deliberate and correct; it is the scaling
   wall once core counts rise. The real fix is a per-mm CPU mask so the
   IPI is skipped for address spaces no other CPU has loaded.
6. **`find_free_address` scans from the base every call.** [audit 2.7]
   O(VMAs) per mmap. The tradeoff is deliberate — a cursor would never
   wrap and freed ranges would never be reused — and only worth
   revisiting if it shows up in a profile.
7. **Path ABI is inconsistent.** [audit 3] `SYS_OPEN` takes a
   NUL-terminated path while `SYS_STAT` takes pointer+length. `edos_rt`
   no longer pays for it — `FileDesc::new` goes through `SYS_OPENAT`
   with `AT_FDCWD`, which behaves exactly like `SYS_OPEN` and needs no
   `CString` — but `edos_lib`, `edos-sh` and the coreutils still call
   the NUL-terminated forms of open, unlink, rename, mkdir and rmdir,
   and the kernel still carries both entry points.

Then, by fun-per-effort:

more tools > dynamic linker > in-EDOS fsck > IPv6 > virtio-net
