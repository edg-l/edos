# EDOS Future Ideas

## Done

- **Network stack** - e1000e driver with MSI-X, ARP, ICMP, UDP, TCP (retransmit,
  flow control), DHCP, DNS resolver, HTTP client, IP fragment reassembly
- **std::net** - TcpStream, UdpSocket wired up in the Rust std fork
- **Socket poll wakeup** - PollEntry registered, indefinite poll wakes on data arrival
- **Custom filesystem (EFS)** - ext2-inspired with extents, replaces FAT32 as root FS.
  Spec in doc/efs.md, shared crate in libs/efs-common/, kernel driver, host mkfs tool
- **USB stack** - xHCI, HID (keyboard/mouse), mass storage with FAT32 mounting
- **Virtio-GPU** - 2D driver, dirty-rect transfers, blob resources, hardware cursor
- **Shell scripting** - Functions, control flow, heredocs, command substitution, tab completion
- **PTY subsystem** - Line discipline, canonical/raw modes
- **Graphics pipeline** - VRAM double buffering, SHM zero-copy compositing, Ayu Dark theme
- **COW fork** - Per-frame refcounting, PTE BIT_9 marker, COW fault handler.
  Shell background jobs (&), subshells (()), jobs/wait builtins
- **Sound** - Intel HDA driver with CORB/RIRB codec commands, BDL DMA ring,
  /dev/dsp device node, userspace `play` command for WAV files
- **AHCI NCQ** - FPDMA commands (32 concurrent slots), per-slot DMA pools,
  lock-free slot allocation, mode exclusion for NCQ/non-NCQ coexistence
- **VFS per-inode locking** - Per-inode RwLock with dentry cache (256 entries).
  Single locking layer in vfs.rs (vfs::read/write/file_info/etc.).
  FileSystem trait all &self, drivers manage internal locks.
  Parallel boot loading (3 binaries via NCQ, 113ms for 11.8MB).
- **Inode-based FS fast path** - read_bytes_ino/write_bytes_ino/file_size_ino
  on FileSystem trait. VFS tries inode-based first, falls back to path-based.
  EFS and Memfs skip directory tree walks on read/write for open files.
- **USB HID ISO keyboard fix** - Fixed 4 wrong/missing keycode mappings for
  European ISO keyboards (< > º ç ´).
- **Shell quoted redirect fix** - parse_command tracks quoted tokens,
  extract_redirects skips them. echo "<" > file works correctly.
- **Heap expansion race fixes** - Lazy vmalloc fault handler, expansion
  serialization (AtomicBool), per-CPU heap freelists (6 size classes,
  16 slots/CPU, batch refill/drain). Removed heap warmup workaround.
- **TLB shootdown IPIs** - TlbShootdown interrupt vector, global
  TlbFlushRequest with atomic bitmask acks. Deferred frame free in
  munmap (unmap PTEs, shootdown, then free). COW fork uses
  tlb_shootdown_all. CPU topology tracking in smp.rs.
- **FSGSBASE** - CR4.FSGSBASE enabled with CPUID probe + fallback.
  get_percpu_data() uses rdgsbase (~1 cycle) instead of rdmsr (~30).
- **Limine 0.6 + bootloader v11** - Crate 0.5->0.6 API migration,
  bootloader v9->v11 for base revision 6. RSDP/DTB addresses virtual
  in rev6 (converted to physical). HHDM now 1GB huge pages.
- **HHDM-based process spawn** - Eliminated CR3 switching during ELF
  loading. Writes to child address space go through HHDM translation
  (copy_to_user/zero_user/write_val_to_user helpers on MemoryManager).
  Fixes TLB shootdown timeouts caused by 100+ms interrupts-off in
  do_spawn. Boot stack guard page removed (inside HHDM huge pages).
- **Dep bumps** - acpi 6.1.1, bytemuck 1.25.0, bitflags 2.11.0
- **O_TRUNC support** - Wired OpenOptions::truncate() through edos_rt
  OpenFlags::TRUNCATE (0x200) to kernel sys_open. File::create and
  std::fs::write now correctly truncate existing files.
- **Per-file fsync** - SYS_FSYNC syscall (14) with per-inode flush path.
  EFS/FAT32 flush_inode() flushes drive write cache only (skips
  superblock/BGD/FSInfo). File::sync_all()/sync_data() wired through
  Rust std. AHCI FUA detection (IDENTIFY word 84 bit 6) and FUA write
  commands (WRITE DMA FUA EXT, WRITE FPDMA QUEUED FUA) added for
  future use.

## Boot Race / Heap Expansion Bug (mostly fixed, intermittent remnant)

All three Linux-inspired fixes are now implemented:
1. **Lazy vmalloc fault handler** -- page fault handler walks kernel PML4
   lock-free for faults in KERNEL_HEAP..VMALLOC_END. If mapping exists,
   invlpg and retry. Handles stale paging-structure cache entries.
2. **Heap expansion serialization** -- AtomicBool EXPANDING ensures only
   one CPU expands at a time. Waiters spin then retry.
3. **Per-CPU heap freelists** -- 6 size classes (32-1024 bytes), 16 slots
   per CPU. Most small allocations avoid the global heap lock. Batch
   refill/drain of 8 objects. FSGSBASE enabled for fast per-CPU access.

TLB shootdown IPIs also implemented for safe page unmapping on SMP
(deferred frame free in munmap, shootdown in COW fork).

The 512KB heap warmup workaround was removed.

Intermittent issue remains: boot-load threads occasionally vanish during
parallel boot (~1 in 5 runs). All CPUs go idle, no panic. Unknown root
cause -- possibly a pre-existing race in the scheduler, VFS, or buddy
allocator metadata corruption under specific allocation patterns. Not
reproducible with sequential boot loading.

## Ideas

### Text Editor
Even a minimal ed/nano clone. Being able to edit files inside the OS is a
qualitative leap in self-sufficiency.

### Demand Paging
Stop pre-faulting all pages. COW fork is done, demand paging is the other half.

### io_uring-style Async I/O
Shared-memory submission/completion ring between userspace and kernel.
Already have the SHM infrastructure. Very "modern OS" feature, unique among hobby OSes.

### IPv6
Full IPv6 support: different header format, NDP (replaces ARP), ICMPv6,
SLAAC/DHCPv6 for address configuration, multicast. Source-only fragmentation
(different model from IPv4). Not urgent since most targets work fine on v4,
but needed for a complete real-hardware network stack.

### virtio-net
Second NIC backend. Straightforward now that the stack and e1000e exist.
Useful for VMs where e1000e emulation is slower than paravirtual.

### EFS parallel extent reads
EfsDriver::read_via_extents reads one extent at a time. For fragmented files
spanning multiple extents, could issue all extent reads concurrently via
ncq_read_batch.

### AHCI zero-copy DMA
Currently AHCI reads/writes copy through intermediate per-slot DMA pool pages
(248 x 4KB scatter-gather pages per slot). Linux avoids this entirely by building
PRDT entries that point directly to page cache pages. Requires page-aligned
buffers from the VFS/page cache layer. Would eliminate the copy-in/copy-out
overhead and reduce DMA memory usage from ~31MB/port to just the command tables.

### More userspace tools
- wget/curl (HTTP client exists, just needs a CLI wrapper)
- env/printenv (environment variable support exists)
- sort, uniq, tee, tr, seq, yes, sleep
- chmod/chown (once EFS has permission support)

## Fun-per-effort ranking

text editor > more tools > demand paging > async I/O > IPv6 > virtio-net
