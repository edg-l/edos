# EDOS Future Ideas

## Network Stack (recommended next)

The single most impactful missing feature. The moment you can ping from your OS
or fetch a page over HTTP, it feels like a real system.

Path:
1. virtio-net driver (easiest in QEMU, well-documented spec, already have virtio-gpu experience)
2. Ethernet + ARP + IPv4 + ICMP - ping working, instant gratification
3. UDP - simple, connectionless, useful for DNS
4. TCP - the real challenge, incredibly educational (state machine, retransmit, flow control)
5. DNS resolver + tiny HTTP client - download a file from the internet inside the OS

### Real hardware NIC: e1000e

Prefer e1000e over virtio-net as first driver:
- QEMU emulates it faithfully, maps to real Intel I219/I218 NICs
- Intel datasheets are public and thorough
- TX/RX descriptor ring design almost identical to AHCI's command ring
- Develop/test in QEMU: -netdev user,id=n -device e1000e,netdev=n
- Same driver works on real Intel NICs on bare metal
- Adding virtio-net later as second backend is straightforward once the stack exists

Other NIC options:
- RTL8139 - classic "baby's first NIC driver", extremely simple but ancient (100Mbps)
- RTL8169/8111 - Realtek gigabit, very common in real hardware, less documented than Intel

## Custom Filesystem (lower priority)

B-tree based, more modern replacement for FAT32. Cool but FAT32 is functional and
the VFS abstracts it away. Can swap it out later without changing userspace.

### IPv6

Full IPv6 support: different header format, NDP (replaces ARP), ICMPv6,
SLAAC/DHCPv6 for address configuration, multicast. Source-only fragmentation
(different model from IPv4). Not urgent since most targets work fine on v4,
but needed for a complete real-hardware network stack.

## Other Ideas

### Sound (high fun-per-effort)
AC97 or Intel HDA driver. Playing a WAV file from the shell is a great demo moment.
AC97 is dead simple compared to networking.

### Copy-on-Write Fork + Demand Paging
Already have mmap and SHM. COW fork makes process spawning way cheaper.
Demand paging means stop pre-faulting all pages.

### Text Editor
Even a minimal ed/nano clone. Being able to edit files inside the OS is a
qualitative leap in self-sufficiency.

### io_uring-style Async I/O
Shared-memory submission/completion ring between userspace and kernel.
Already have the SHM infrastructure. Very "modern OS" feature, unique among hobby OSes.

## Fun-per-effort ranking

networking > sound > text editor > async I/O > COW fork > custom FS

## Remaining Network Stack Items

- Wire up `std::net` in the Rust std fork (TcpStream, UdpSocket, etc.)
- Socket poll wakeup: register PollEntry so indefinite poll wakes on data arrival
- TCP: SACK, window scaling, Nagle's algorithm, adaptive RTO (SRTT/RTTVAR)
- DHCP lease renewal
- IPv6 (header format, NDP, ICMPv6, SLAAC/DHCPv6, source-only fragmentation)
- DNS: proper resolver (currently hardcoded transaction ID, no caching)
- `sys_recvfrom`: MSG_TRUNC support, validate caller's addr_len
- Use `next_ip_id()` in IPv4 build (currently always id=0)
