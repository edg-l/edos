- **Boot hang fix** - Root cause was switch_to_kernel_page() calling
  tlb_flush_all_including_global() unconditionally (even when CR3
  didn't change), creating a TLB storm during parallel boot that
  triggered cascading vmalloc faults. Combined with IST re-entrancy
  (nested page fault on IST 1 clobbered the outer handler's stack
  frame), this caused all CPUs to get stuck. Fix: removed the
  unconditional global TLB flush (Cr3::write already flushes
  non-globals), and moved page fault handler off IST onto the
  regular kernel stack so nested faults work naturally. Double fault
  handler retains its own IST for stack overflow protection.
  20/20 boot test passes (was ~1 in 5 failure rate).
- **Scheduler park/wake race fix (2026-04-13)** - Added wake-pending
  token (Thread.wake_pending: AtomicBool). Wakers signal_wake() before
  probing state; parkers consume_wake_pending() after CAS to Parked/
  Sleeping and revert to Running if set. Closes the lost-wakeup race
  for thread_park, thread_park_while, and thread_sleep at the primitive
  level. wake_thread_slow + wake_thread_from_irq collapsed to one
  do_wake; retry loop / MAX_RETRIES / spin_loop deleted. New transition
  Sleeping->Running for sleep abort. thread_park_while now LOOPS on
  spurious-wake (token consumed but closure still says park) so callers
  without their own outer loop (sys_waitpid in particular) are correct
  by contract. Fixes the intermittent boot hang documented in
  doc/bugs/2026-04-13-sched-park-wake-missed-wakeup.md
  AND the shell-dies-after-`ls` symptom seen during testing. Debug
  visibility: Thread.last_syscall + dump_threads.gdb shows SYSCALL and
  WP columns per thread.
- **EFS host fsck (storage roadmap step 4)** - `tools/efs-fsck/` host
  tool: SB/BGD cross-check, journal replay (port of kernel's two-pass
  algorithm via shared `libs/efs-common/journal_parse.rs`), inode scan
  with extent validation, block+inode bitmap rebuild and leak/double-
  claim detection, directory-tree walk with `.`/`..` and link-count
  reconciliation. `--repair` opts into 5 fix classes (leaked block
  bits, leaked inode bits, BGD/SB free-count sums, link-count fixes,
  orphan deletion) with per-class prompts (`-y` to auto-accept) and
  Linux-style exit codes (0/1/4/8/16). `fsck_in_progress` byte stolen

  reruns (`--force` to override). Double-claim guard skips bitmap
  clears for blocks also held by live inodes. 8 integration tests +
  `doc/efs-fsck.md`.
- **Lazy ELF relocation (2026-04-13)** - Replaced eager R_X86_64_RELATIVE
  pass with on-demand patching driven by the page fault handler. Per-process
  Arc<RelocTable> with per-page bucket index parsed at load_elf; fault path
  early-COWs reloc-target pages (allocate private frame, copy from cache,
  apply relocs, map writable, never patch shared cache). Partial-last-file-

  already-mapped pages). Cold-spawn /bin/sh from terminal: 238ms -> 162ms
  (-32%). Boot-time parallel loads unchanged (already I/O-bound). Foundation
  for future dynamic linker. Does not yet shrink time-to-/bin/sh because
  boot-load kthreads are already parallel and AHCI-bound; gain is on serial
  cold spawns.
- **File-backed mmap (MAP_PRIVATE + MAP_SHARED)** - VmaBacking::FileBacked
  with Arc<VfsInode> + Arc<CachedPage>-per-page on the VMA. MAP_PRIVATE
  installs read-only + COW_BIT, writes fault into anon via the existing
  COW handler. MAP_SHARED installs writable, dirty-marks unconditionally
  on first fault, flushes via PageCacheOps::flush_page on msync, munmap,
  process exit, and periodically from the writeback kthread (global
  DIRTY_INODES Weak registry, IrqSpinlock so fault-handler registration
  is safe). VmaSet::split_at + remove_range enable partial munmap.
  Truncate walks a per-inode mappers reverse-map and unmaps invalidated

  Past-EOF access kills the faulting thread (code 11). sys_msync (SYS=34)
  and edos_rt 0.0.35 (READ_ONLY/WRITE_ONLY/READ_WRITE OpenFlags wired
  through the Rust std's OpenOptions.read/write). 7-test userspace
  mmaptest (MAP_PRIVATE read, COW write, MAP_SHARED + msync, two-mapper
  visibility, past-EOF kill in forked child, truncate invalidation kill,
  fsync+msync round-trip) all pass on EFS. FAT32 / memfs return EINVAL
  (no PageCacheOps). Side win: fixed a latent map_address bug where
  read-only user mappings created intermediate PML2 entries without
  WRITABLE, poisoning the 2 MiB range for later writable mappings (was
  causing wm to crash after 30s of SHM cycling); debug_assert_permissive
  _parents catches regressions.
- **ElfSegment -> FileBacked migration (2026-04-12)** - ELF loader no
  longer keeps the binary as Arc<Vec<u8>>. load_elf takes Arc<VfsInode>
  + Path; per-PT_LOAD it builds VmaBacking::FileBacked { inode,
  file_offset, shared:false, writable_mapping, pages } reusing the
  per-inode page cache, plus a separate Anonymous VMA for the BSS tail
  past the last file page. Partial last file page is eagerly zero-padded.
  Bulk-prefetch via prefetch_file_pages still feeds the eager-reloc pass
  (writable .data pages COW-materialize at load time because RELATIVE

  inode.mappers for truncate invalidation. VmaBacking::ElfSegment,
  load_elf_from_bytes, FaultSource::ElfData and their fault/free arms all

  per-process full-binary copy. Prerequisite for the dynamic linker. Note:
  binaries on FAT32 / memfs return ENOEXEC until those FSes implement
  PageCacheOps.
- **Arc/Weak thread handles (Foundation #1, 2026-04-16)** - Replaced
  raw TID storage in every sync primitive and IRQ-reachable static with

- **Cancellable waits + deferred VfsInode eviction (Foundation #2, 2026-04-17)** -

- **Physical frame RAII for CachedPage (Foundation #3, 2026-04-17)** -

## Boot Race / Heap Expansion Bug (fixed)

All fixes implemented:
1. **Lazy vmalloc fault handler** -- page fault handler walks kernel PML4
   lock-free for faults in KERNEL_HEAP..VMALLOC_END. If mapping exists,
   invlpg and retry. Handles stale paging-structure cache entries.
2. **Heap expansion serialization** -- AtomicBool EXPANDING ensures only
   one CPU expands at a time. Waiters spin then retry.
3. **Per-CPU heap freelists** -- 6 size classes (32-1024 bytes), 16 slots
   per CPU. Most small allocations avoid the global heap lock. Batch
   refill/drain of 8 objects. FSGSBASE enabled for fast per-CPU access.
4. **TLB flush fix** -- switch_to_kernel_page() no longer calls
   tlb_flush_all_including_global() unconditionally. Cr3::write
   already flushes non-global entries. The unconditional global flush
   was the root trigger for the intermittent boot hang.
5. **Page fault off IST** -- Page fault handler uses the kernel stack
   instead of IST 1. Nested page faults (vmalloc fault during demand
   fault handling) work naturally. Double fault retains its own IST
   for stack overflow protection.

TLB shootdown IPIs also implemented for safe page unmapping on SMP
(deferred frame free in munmap, shootdown in COW fork).

The 512KB heap warmup workaround was removed. 20/20 boot passes
(was ~1 in 5 failure rate).

## Open questions / loose ends

### Transient boot GPF — ROOT-CAUSED 2026-04-15 (frame allocator aliasing)
Earlier "transient boot GPF" in `IntrusiveList::push_back` with a
non-canonical head/tail was a secondary symptom of a bigger bug:
the physical frame allocator was handing out the same phys frame
twice (heap ↔ vmalloc DMA). virtio-gpu DMA response data was
overwriting scheduler runqueue memory, producing the non-canonical
pointer.

Root cause: `MemoryManager::map_address` / `map_address_range` set
the bitmap bit for the target phys but did not bump the refcount.
`unmap_memory`'s `deallocate_frame` later decremented a refcount
that was never incremented — when the phys was ALSO held by a
heap mapping (refcount=1 from `allocate_frame`), the decrement
took it to 0, cleared the bitmap bit, and the next allocation
returned that still-mapped frame.

Fix: `map_address` now calls `inc_or_set_refcount` instead of
`set_frame_allocated`. Each mapping holds a real refcount; the
final unmap drops to 0 and clears the bit.

Regression guard: `memory::verify_kernel_no_phys_aliasing()` runs
at the end of `init_drivers()` and panics if any kernel-half phys
is mapped at two virts. Also a hard `assert!` in
`BitmapFrameAllocator::deallocate_frame` catches refcount-0 double
free. The intrusive-list canonical-address debug_assert stays as
defense in depth.

### Warm spawn latency regression after inode_cache removal
Removing `EfsDriver::inode_cache` was correct design (one cache,
not two) but warm `/bin/ps` load went from ~0.2ms (pre-block-cache,
BTreeMap hit) to ~6ms (block page cache lookup + inode parse). Not
urgent — 6ms is fine absolutely — but if warm spawn latency
matters later, add a tiny CPU-local inode parse cache (say 8
entries, FIFO) in EFS to avoid re-parsing the same inode on every
open.

### FAT32 full-cluster write vs RMW
Aligned full-page writes now skip RMW. Cluster writes that are
smaller than a page (e.g. 512B sector with cluster_size=1) still
RMW. Fine for FAT32's small-sector case; document or optimize if
cluster_size starts mattering.

### Scheduler balance: parked-thread migration + wake-to-idle (not fixed)
Observed 2026-04-15 via `ps`: 13 kernel+user threads ended up parked
on CPU 3 while CPUs 0/1/2 each had 2 threads. The biased placement
traced to `pick_sched()`: sorted-lapic iteration + `>=` tie-break made
CPU 3 (last iterated) effectively never win ties, so early boot spawns
that all saw `thread_count=0` initially packed onto one CPU via a
different cascade. Fixed 2026-04-15 by switching `pick_sched` to a
rotating tie-break (`PICK_SCHED_ROTATION: AtomicU32` bumps each call),
so new spawns with equal counts round-robin across CPUs.

Not fixed: existing parked threads stay on their original CPU forever.
Work-stealing only moves Ready/Running. A driver kthread that parks on
CPU X stays on CPU X, gets enqueued back to CPU X's rq on wake. Two
follow-ups worth doing when scheduler load-balancing matters:

1. Let work-stealing steal parked threads too, OR a periodic rebalance
   pass that migrates parked threads from overloaded CPUs.
2. Wake-to-idle hint: when `wake_thread_handle` fires and the target
   thread's home CPU is loaded AND another CPU is idle, redirect the
   wake to the idle CPU's rq. Cleaner to do post-Foundation-#1 since
   the wake path already takes a `Weak<Thread>` handle.

### Driver kthread startup starvation on busy CPU
Observed 2026-04-15: mouse kthread can take up to 5 seconds to
start running because `pick_sched()` at spawn time placed it on the
same CPU as the e1000e driver kthread, which was blocked on DHCP
for ~5 seconds. Meanwhile `edos-wm` spawned by `system-mount` at
~1.5s tried `open("/dev/mouse")`, got `InvalidInput` (device not
yet registered in devfs), panicked, and exited. No automatic retry.

Two issues conflate here:
1. Scheduler places cooperative-blocked-driver kthreads and
   latency-sensitive driver kthreads on the same CPU, starving the
   latter until the former unblocks.
2. Userspace programs assume their required `/dev/*` entries exist
   at program start. They don't (drivers register async).

Fix options, ranked:
- (best) `system-mount` should wait for `/dev/mouse` and `/dev/kbd`
  to exist before spawning `edos-wm` (and any program that depends
  on input). Possibly a generic "wait for device" syscall or a
  `/dev/.ready` sentinel.
- edos-wm retries `open("/dev/mouse")` with backoff instead of
  panicking on first failure.
- `queue_spawn_kthread_named_on(cpu)` variant so mouse and keyboard
  go to specifically different CPUs from network drivers.
- Convert DHCP wait from `thread_park_while` on a 5s hard timeout
  to an event-driven kthread that yields between short polls.

## Ideas

### Foundations for async I/O (TOP PRIORITY, unblocks multiple features)

Discovered while planning async NCQ readahead
(`.claude/plans/async-ncq-readahead.md`): AHCI already supports
concurrent NCQ slots and IRQ-driven wake, but a split `submit/wait` API
is unsafe today because of generic kernel-infrastructure gaps. These
aren't "async is hard" issues — they are missing foundations that also
affect other planned work (proper SIGKILL delivery, process-level
cleanup on exec, multi-threaded file I/O, virtio-blk / USB async reads,
reaper correctness in general). Roadmap in dependency order:

1. **Thread handles with Arc / Weak refcounting instead of raw TIDs.**
   **DONE 2026-04-16.** `Scheduler::wake_thread` / `wake_thread_irq`
   now take `&Weak<Thread>` exclusively; the TID-based API is deleted.
   Every sync primitive (WaitQueue, PollWaiter, Subscriber, AHCI
   slot_waiters, ThreadExitRegistry waiters, every driver dispatcher
   thread handle, REAPER_HANDLE, kill_process) stores `Weak<Thread>`.
   A dangling Weak upgrades to `None` → `wake_thread*` is a silent
   no-op instead of waking a recycled TID's successor. See CLAUDE.md
   "Thread handles" invariant and `.claude/plans/arc-weak-thread-handles.md`.

2. **Cancellable / transferable waits for dying threads.** When a
   thread is killed (SIGKILL, process group termination) while parked
   on I/O, the reaper needs a way to hand off ownership of the
   pending resource (kernel cleanup thread, destination page cache).
   Today the reaper just drops the stack, so anything with a blocking
   Drop deadlocks the reaper. Pieces: a "cleanup queue" the reaper
   drains, `Drop` contracts that never block, per-thread list of
   owned async resources. Prereq for real signal handling too.

3. **Physical frame RAII for cache pages.** **DONE 2026-04-17.**
   `CachedPage::drop` deallocates the frame on last Arc drop (mirrors
   `CachedBlockPage::drop`). Removed the manual `deallocate_frame` in
   `InodePages::get_or_fill`'s race-insert path and the
   `strong_count == 1` heuristic in `invalidate_from`. Debug assert on
   `pin_count == 0` at drop caught a pre-existing pin leak in
   `store_cached_page_on_vma` (fixed: unpin at entry).

4. **Strict lock-order discipline for fs/page-cache paths.**
   **DONE 2026-04-17.** Canonical rank table in
   `doc/invariants/lock-order.md` (ranks 10-200). Per-thread rank
   stack (`Thread.lock_ranks`, `heapless::Vec`, debug only) enforced
   by `ranked_lock!` / `ranked_read!` / `ranked_write!` macros and
   `RankedGuard<G>` (ManuallyDrop-based RAII). All 20 ranked lock
   sites across VFS, page-cache, journal, EFS, AHCI, frame allocator,
   and memory manager instrumented. Pre-existing journal
   `tracker->state` AB/BA inversion fixed. `/proc/lock_order_stats`
   exposes inversion count and max stack depth. `lockordertest`
   program verifies inversions==0 after a representative workload.
   See `.claude/plans/foundation-4-lock-order.md`.

5. **Per-inode async I/O registry (last layer, uses #1-#4).**
   `InodePages` gets an `in_flight: BTreeMap<page_idx, Arc<PageFillHandle>>`
   that readers consult before issuing their own fill. Handle lives
   longer than any single thread, carries the Arc<CachedPage>s being
   populated, has a WaitQueue readers park on. Removal from the map
   atomic with either "publish to pages map" (success) or "mark error
   and let next reader retry" (failure).

6. **Generic async block I/O trait.** Today AHCI is the only disk.
   Async readahead should live behind a generic trait so USB mass
   storage, virtio-blk (future), and NVMe all get it. Light lift
   once #1-#5 are in place.

Each of #1-#5 is ~1-2 sessions of careful work; #6 is light. This is
higher priority than any other idea below because it unblocks async
readahead, proper signal handling, safer thread cancellation, and the
long-term I/O story across all block devices. See the async readahead
entry below for the specific payoff on file-read performance.

### Async NCQ pipelined readahead (blocked on Foundations above)

Linux's async-marker readahead: when the user reads the last page of
the current window, the kernel pre-fires the NEXT window's I/O so it
completes while the user consumes the current batch, keeping the I/O
pipeline full. Current EDOS readahead is sync-only, so steady-state
64 KiB user reads still trigger 64 KiB AHCI commands — the prefetch
window follows the user rather than pulling ahead. Small-file whole-
file prefetch (shipped 2026-04-15) covers files ≤ 2 MiB; async is
needed for the large-file case.

Design is already drafted in `.claude/plans/async-ncq-readahead.md`
(5 phases, ~400 LOC). First review found 4 BLOCKERs, all of which
trace back to the Foundations roadmap above. Do NOT try to implement
this until the Foundations are in place; otherwise we will re-hit the
same design walls.

Payoff once Foundations + this land: first-run mmaptest test 10 on
/var EFS drops from ~500 ms (current, with whole-file prefetch) to
~150 ms; concurrent-read throughput improves across the board;
writeback/read overlap becomes possible.

### EFS write-path perf: batch journal tx per flush_dirty round (DONE 2026-04-15)
Shipped as commit `824e656`. Added `PageCacheOps::flush_pages_bulk`
with a default per-page loop; EFS overrides to chunk pages in 512-page
batches, each with one TxHandle and one `ensure_blocks_for_logical_batch`
(read inode once, walk all logical blocks with extent coalescing, write
inode once). Direct AHCI page writes bypass BlockPageCache. Also added
`InodePages::flush_dirty_bulk` with all-or-nothing semantics. vfs
`flush_file` and `flush_dirty_inodes` migrated. mmaptest test 7
(fsync+msync) on /var EFS: ~4.1s → 159ms (26x).

### EFS write-path perf: sequential-extent pre-allocation (up next after batching)
`flush_page` currently allocates one cluster at a time via
`ensure_block_for_logical`, which walks the extent tree per call and
splits what could have been one contiguous extent into many tiny
ones. For a growing file, we should detect the "append pattern" and
pre-allocate a contiguous extent of N blocks up front (maybe 32 or
64), then let subsequent `flush_page` calls land inside the already-
allocated range without walking/appending the extent tree. This
matches ext4's delayed allocation + multi-block allocator (mballoc).
Payoffs: fewer extent-tree entries on disk (less metadata to flush),
fewer bitmap updates (one BGD transaction per big alloc, not 480),
contiguous data on disk (faster reads later).

### PageCacheOps for FAT32 + memfs
Today only EFS implements PageCacheOps, so file-backed mmap (and the
new FileBacked ELF loader) returns EINVAL/ENOEXEC on FAT32 and memfs.
Binaries copied to a USB FAT32 drive cannot exec, and mmap'ing files on
/tmp falls back to read+anon. Wiring PageCacheOps through both drivers
unblocks both paths.

### Dynamic Linker (ld.so)
ELF dynamic linking: PT_INTERP, PT_DYNAMIC parsing, symbol resolution
(DT_HASH/DT_GNU_HASH), PLT/GOT lazy binding, dlopen/dlsym/dlclose.
Requires General Dynamic TLS model + DTV (dynamic thread vector).
Shared libraries share physical pages across processes via MAP_SHARED
file-backed mmap. Enables C library use, plugin systems, and shared
memory savings. Natural ordering: page cache -> file-backed mmap ->
dynamic linker.

### io_uring-style Async I/O
Shared-memory submission/completion ring between userspace and kernel.
Already have the SHM infrastructure. Very "modern OS" feature, unique among hobby OSes.

### IPv6
Full IPv6 support: different header format, NDP (replaces ARP), ICMPv6,
SLAAC/DHCPv6 for address configuration, multicast. Source-only fragmentation
(different model from IPv4). Not urgent since most targets work fine on v4,
but needed for a complete real-hardware network stack.

### virtio-net
Second NIC backend. Straightforward now that the stack and e1000e exist.
Useful for VMs where e1000e emulation is slower than paravirtual.

### EFS parallel extent reads
EfsDriver::read_via_extents reads one extent at a time. For fragmented files
spanning multiple extents, could issue all extent reads concurrently via
ncq_read_batch.

### SIGINT delivery to foreground processes
Ctrl+C in the terminal doesn't kill foreground processes. Tools that read
stdin (wc, sort, uniq, tee, tr, cat with no args) hang with no way to
interrupt them. Need proper signal delivery from PTY/terminal to the
foreground process group.

### More userspace tools
- chmod/chown (once EFS has permission support)
- printenv (alias for env)
- basename, dirname, id, whoami, date

### In-EDOS fsck (`/bin/fsck`)
Host `efs-fsck` is the canonical recovery tool. A thinner in-EDOS
userspace wrapper would be useful for unmounted secondary block
devices (USB drives, second SATA, attached image files). Cannot fsck
the live root FS without an initramfs (chicken-and-egg), and EDOS has
none — kernel still replays journal automatically on mount, which
covers the common boot case. Code reuse: `libs/efs-common` is already
`no_std` and works in userspace; the host crate's `std::fs::File`
calls would swap for `open("/dev/sdb")` + `pread`/`pwrite`/`fsync`.

**Prereq investigation**: check `kernel/src/fs/devfs/` to see what
`/dev/sda` exposes today. Raw block-device-as-file (open+pread on a
sector-aligned device node) may not be wired. If it isn't, that's the
first piece to land before any in-EDOS fsck makes sense.

## Fun-per-effort ranking

more tools > dynamic linker > PageCacheOps for FAT32+memfs > in-EDOS
fsck > async I/O > IPv6 > virtio-net

Note: storage-stack roadmap steps 1-4 are all shipped (host fsck done).
File-backed mmap, ElfSegment->FileBacked loader migration, and lazy ELF
relocation are all shipped. The next step in the memory/loader
progression toward the dynamic linker is PageCacheOps for FAT32+memfs
(so binaries on USB drives can exec) or PT_INTERP / dynamic linker
support itself.
