# EDOS Future Ideas

## Done

- **Network stack** - e1000e driver with MSI-X, ARP, ICMP, UDP, TCP (retransmit,
  flow control), DHCP, DNS resolver, HTTP client, IP fragment reassembly
- **std::net** - TcpStream, UdpSocket wired up in the Rust std fork
- **Socket poll wakeup** - PollEntry registered, indefinite poll wakes on data arrival
- **Custom filesystem (EFS)** - ext2-inspired with extents, replaces FAT32 as root FS.
  Spec in doc/efs.md, shared crate in libs/efs-common/, kernel driver, host mkfs tool
- **USB stack** - xHCI, HID (keyboard/mouse), mass storage with FAT32 mounting
- **Virtio-GPU** - 2D driver, dirty-rect transfers, blob resources, hardware cursor
- **Shell scripting** - Functions, control flow, heredocs, command substitution, tab completion
- **PTY subsystem** - Line discipline, canonical/raw modes
- **Graphics pipeline** - VRAM double buffering, SHM zero-copy compositing, Ayu Dark theme
- **COW fork** - Per-frame refcounting, PTE BIT_9 marker, COW fault handler.
  Shell background jobs (&), subshells (()), jobs/wait builtins
- **Sound** - Intel HDA driver with CORB/RIRB codec commands, BDL DMA ring,
  /dev/dsp device node, userspace `play` command for WAV files
- **AHCI NCQ** - FPDMA commands (32 concurrent slots), per-slot DMA pools,
  lock-free slot allocation, mode exclusion for NCQ/non-NCQ coexistence
- **VFS per-inode locking** - Per-inode RwLock with dentry cache (256 entries).
  Single locking layer in vfs.rs (vfs::read/write/file_info/etc.).
  FileSystem trait all &self, drivers manage internal locks.
  Parallel boot loading (3 binaries via NCQ, 113ms for 11.8MB).
- **Inode-based FS fast path** - read_bytes_ino/write_bytes_ino/file_size_ino
  on FileSystem trait. VFS tries inode-based first, falls back to path-based.
  EFS and Memfs skip directory tree walks on read/write for open files.
- **USB HID ISO keyboard fix** - Fixed 4 wrong/missing keycode mappings for
  European ISO keyboards (< > º ç ´).
- **Shell quoted redirect fix** - parse_command tracks quoted tokens,
  extract_redirects skips them. echo "<" > file works correctly.
- **Heap expansion race fixes** - Lazy vmalloc fault handler, expansion
  serialization (AtomicBool), per-CPU heap freelists (6 size classes,
  16 slots/CPU, batch refill/drain). Removed heap warmup workaround.
- **TLB shootdown IPIs** - TlbShootdown interrupt vector, global
  TlbFlushRequest with atomic bitmask acks. Deferred frame free in
  munmap (unmap PTEs, shootdown, then free). COW fork uses
  tlb_shootdown_all. CPU topology tracking in smp.rs.
- **FSGSBASE** - CR4.FSGSBASE enabled with CPUID probe + fallback.
  get_percpu_data() uses rdgsbase (~1 cycle) instead of rdmsr (~30).
- **Limine 0.6 + bootloader v11** - Crate 0.5->0.6 API migration,
  bootloader v9->v11 for base revision 6. RSDP/DTB addresses virtual
  in rev6 (converted to physical). HHDM now 1GB huge pages.
- **HHDM-based process spawn** - Eliminated CR3 switching during ELF
  loading. Writes to child address space go through HHDM translation
  (copy_to_user/zero_user/write_val_to_user helpers on MemoryManager).
  Fixes TLB shootdown timeouts caused by 100+ms interrupts-off in
  do_spawn. Boot stack guard page removed (inside HHDM huge pages).
- **Dep bumps** - acpi 6.1.1, bytemuck 1.25.0, bitflags 2.11.0
- **O_TRUNC support** - Wired OpenOptions::truncate() through edos_rt
  OpenFlags::TRUNCATE (0x200) to kernel sys_open. File::create and
  std::fs::write now correctly truncate existing files.
- **Per-file fsync** - SYS_FSYNC syscall (14) with per-inode flush path.
  EFS/FAT32 flush_inode() flushes drive write cache only (skips
  superblock/BGD/FSInfo). File::sync_all()/sync_data() wired through
  Rust std. AHCI FUA detection (IDENTIFY word 84 bit 6) and FUA write
  commands (WRITE DMA FUA EXT, WRITE FPDMA QUEUED FUA) added for
  future use.
- **AHCI zero-copy DMA** - Build PRDT entries directly from caller
  buffer physical pages, eliminating per-I/O memcpy through DMA pool
  pages. Translates virt-to-phys per page via memory_mapper(),
  merges contiguous frames, falls back to pool-copy on translation
  failure or odd-aligned buffers. Applied to NCQ read/write,
  NCQ batch read, and legacy ATA read/write paths.
- **Demand paging** - VMA subsystem (VmaSet replaces MemoryMapping/
  MemoryRegion), anonymous zero-fill on fault, lazy ELF loading
  (segments faulted from stored Arc<Vec<u8>>), lazy stack growth.
  MemoryManager owns VmaSet (like Linux mm_struct) so copy_to_user
  can demand-fault during thread construction. Shared fault_in_page
  used by both IST handler and HHDM translate path.
- **Per-inode page cache (EFS file data)** - Linux-style address_space
  per VfsInode: BTreeMap<page_idx, Arc<CachedPage>> + BlockingMutex.
  PageCacheOps trait on FileSystem (fill_page, fill_pages_bulk,
  flush_page, update_size). Bulk fill path does one multi-block AHCI
  read then distributes into per-page entries (Linux readahead style).
  Direct AHCI I/O bypassing BlockDevice (INVARIANT, preserved). Stays
  write-through for now; file-data write-back can come later.
- **Block-device page cache (storage roadmap step 1)** - 4 KiB-page
  cache keyed by (device_id, block), 8 LRU shards x 256 = 2048-page
  ceiling. Replaces the old 512 B sector LRU on BlockDevice. EFS
  read_block/write_block, inode/BGD/bitmap reads, and FAT32 metadata
  all go through it. Per-page write_lock serializes RMW. /proc/block_cache
  exposes hits/misses/evictions. inode_cache removed from EfsDriver.
- **Write-back metadata cache (storage roadmap step 2)** - write_page /
  write_partial_page mark dirty + return; background block_writeback
  kthread flushes every 5s or on kick. flush_requested / flush_completed
  AtomicU64 counters form a race-free sync barrier. flush_device calls
  AHCI FLUSH CACHE after writeback (fsync reaches platter). sys_sync
  (162) added; /bin/sync tool. system-mount wall: 1379ms -> 972ms.
  CRASH SAFETY: write-back without journal means crash mid-mkdir can
  corrupt the FS. Journal (step 3) fixes.
- **Kernel lifetime logging** - spawn: / exit: log lines with load time
  (do_spawn duration), wall time (thread creation -> exit), cpu time
  (scheduler accounting), and demand_faults count. Revealed ~140x
  cold/warm page-cache speedup on binary loads and mkdir being the
  bottleneck in system-mount.
- **Kernel debug_asserts** - is_canonical() pointer checks on
  intrusive_list push_back/push_front/unlink. pin_count==0 on
  CachedBlockPage::drop. Frame-alignment checks in the block cache.
  spawn_thread state check. Zero release cost; catches pointer
  corruption / leaked guards early.
- **pick_sched lapic_id fix** - SCHEDULERS is keyed by lapic_id, not
  sequential index. Previous code iterated 0..num_cpus treating i as
  lapic_id; works on QEMU, broken on real hardware with sparse lapic
  IDs. Now iterates values directly.
- **EFS metadata journal (storage roadmap step 3)** - jbd2-style WAL
  for crash-safe metadata. On-disk ring (default 16 MiB, reserved at
  mkfs). TxHandle RAII wraps every metadata op (create/remove file/dir,
  rename, truncate); enrolls dirty pages + revoke records for freed
  blocks. Committer kthread seals active tx every 1s, writes
  descriptor+data+revoke+FUA commit to the ring. Writeback gated:
  dirty pages don't flush to home location until their tx is committed.
  Two-pass replay on mount: pass 1 builds revoke set, pass 2 applies
  committed data blocks (skipping revoked). CRC-verified commits,
  magic-escaped data blocks. DescriptorEntry 16B with flags field.
  Block-level ring capacity tracking (head_block/tail_block).
  sys_sync/sys_fsync force-commit with 30s timeout.
  INCOMPAT_JOURNAL feature bit; old images must be reformatted.
  /bin/sync tool. system-mount wall: 1379ms -> 808ms.
- **VFS page_cache_read EOF fix** - page_cache_read returned full count
  bytes past EOF (zero-filled cached pages). read_to_end looped
  forever. Fix: VFS read() clamps to file_size_ino before page cache.
- **EFS file-data I/O path consistency** - write_via_extents and all
  directory-data reads now correctly use their designated paths:
  file data via direct AHCI (matching read_via_extents), directory
  data via read_dir_data_cached (through block page cache, matching
  write_block). Prevents stale-data bugs with write-back metadata.
- **Boot hang fix** - Root cause was switch_to_kernel_page() calling
  tlb_flush_all_including_global() unconditionally (even when CR3
  didn't change), creating a TLB storm during parallel boot that
  triggered cascading vmalloc faults. Combined with IST re-entrancy
  (nested page fault on IST 1 clobbered the outer handler's stack
  frame), this caused all CPUs to get stuck. Fix: removed the
  unconditional global TLB flush (Cr3::write already flushes
  non-globals), and moved page fault handler off IST onto the
  regular kernel stack so nested faults work naturally. Double fault
  handler retains its own IST for stack overflow protection.
  20/20 boot test passes (was ~1 in 5 failure rate).
- **Scheduler park/wake race fix (2026-04-13)** - Added wake-pending
  token (Thread.wake_pending: AtomicBool). Wakers signal_wake() before
  probing state; parkers consume_wake_pending() after CAS to Parked/
  Sleeping and revert to Running if set. Closes the lost-wakeup race
  for thread_park, thread_park_while, and thread_sleep at the primitive
  level. wake_thread_slow + wake_thread_from_irq collapsed to one
  do_wake; retry loop / MAX_RETRIES / spin_loop deleted. New transition
  Sleeping->Running for sleep abort. thread_park_while now LOOPS on
  spurious-wake (token consumed but closure still says park) so callers
  without their own outer loop (sys_waitpid in particular) are correct
  by contract. Fixes the intermittent boot hang documented in bug.txt
  AND the shell-dies-after-`ls` symptom seen during testing. Debug
  visibility: Thread.last_syscall + dump_threads.gdb shows SYSCALL and
  WP columns per thread.
- **File-backed mmap (MAP_PRIVATE + MAP_SHARED)** - VmaBacking::FileBacked
  with Arc<VfsInode> + Arc<CachedPage>-per-page on the VMA. MAP_PRIVATE
  installs read-only + COW_BIT, writes fault into anon via the existing
  COW handler. MAP_SHARED installs writable, dirty-marks unconditionally
  on first fault, flushes via PageCacheOps::flush_page on msync, munmap,
  process exit, and periodically from the writeback kthread (global
  DIRTY_INODES Weak registry, IrqSpinlock so fault-handler registration
  is safe). VmaSet::split_at + remove_range enable partial munmap.
  Truncate walks a per-inode mappers reverse-map and unmaps invalidated
  PTEs across every live mapper process with per-process TLB shootdown.
  Past-EOF access kills the faulting thread (code 11). sys_msync (SYS=34)
  and edos_rt 0.0.35 (READ_ONLY/WRITE_ONLY/READ_WRITE OpenFlags wired
  through the Rust std's OpenOptions.read/write). 7-test userspace
  mmaptest (MAP_PRIVATE read, COW write, MAP_SHARED + msync, two-mapper
  visibility, past-EOF kill in forked child, truncate invalidation kill,
  fsync+msync round-trip) all pass on EFS. FAT32 / memfs return EINVAL
  (no PageCacheOps). Side win: fixed a latent map_address bug where
  read-only user mappings created intermediate PML2 entries without
  WRITABLE, poisoning the 2 MiB range for later writable mappings (was
  causing wm to crash after 30s of SHM cycling); debug_assert_permissive
  _parents catches regressions.

## Boot Race / Heap Expansion Bug (fixed)

All fixes implemented:
1. **Lazy vmalloc fault handler** -- page fault handler walks kernel PML4
   lock-free for faults in KERNEL_HEAP..VMALLOC_END. If mapping exists,
   invlpg and retry. Handles stale paging-structure cache entries.
2. **Heap expansion serialization** -- AtomicBool EXPANDING ensures only
   one CPU expands at a time. Waiters spin then retry.
3. **Per-CPU heap freelists** -- 6 size classes (32-1024 bytes), 16 slots
   per CPU. Most small allocations avoid the global heap lock. Batch
   refill/drain of 8 objects. FSGSBASE enabled for fast per-CPU access.
4. **TLB flush fix** -- switch_to_kernel_page() no longer calls
   tlb_flush_all_including_global() unconditionally. Cr3::write
   already flushes non-global entries. The unconditional global flush
   was the root trigger for the intermittent boot hang.
5. **Page fault off IST** -- Page fault handler uses the kernel stack
   instead of IST 1. Nested page faults (vmalloc fault during demand
   fault handling) work naturally. Double fault retains its own IST
   for stack overflow protection.

TLB shootdown IPIs also implemented for safe page unmapping on SMP
(deferred frame free in munmap, shootdown in COW fork).

The 512KB heap warmup workaround was removed. 20/20 boot passes
(was ~1 in 5 failure rate).

## Storage Stack Roadmap

Starting point: system-mount kthread wall=1379ms, cpu=326ms (~1s of
I/O stall). Three create_dir calls for /dev, /proc, /tmp cost ~720ms.

Steps 1-3 are done (see Done section). Current system-mount wall:
~808ms. FS IS crash-safe for metadata (journal replays on mount).

### 4. fsck tool (next)

Host tool (like efs-mkfs): scan inodes, verify bitmaps, reclaim leaked
blocks, replay journal if mounted dirty. Needed once the journal exists
to make recovery actually trustworthy.

**Why this order**: steps 1-3 are shipped. fsck is the remaining
piece — it scans inodes/bitmaps for consistency and replays the
journal if mount was dirty. Needed to make recovery trustworthy
beyond what replay alone provides (e.g. leaked blocks after a
revoke-less crash, bitmap inconsistencies).

## Open questions / loose ends

### Transient boot GPF — root cause unknown
During the block page cache development, one boot hit a GPF at
`IntrusiveList::push_back`, error code 0x0, non-canonical pointer
write at `(*self.tail).next = link`. Fault did not reproduce after
the following unrelated changes landed:
- `Drop for CachedBlockPage` (replaced manual deallocate_frame)
- `read_via_extents` bypass (file-data out of the block cache)

Inspection of allocator, scheduler, runqueue, intrusive list, SMP
init found no concrete race that could produce a non-canonical
`self.tail` during boot kthread spawn. Hypothesis: timing-sensitive
cross-CPU `spawn_thread` + `on_tick` race; not deterministic.

Mitigation in place: `debug_assert!(is_canonical(...))` on
push_back/push_front/unlink pointer fields. Next time the GPF
appears, one of those will fire with a clear message pointing at
exactly which pointer went bad.

### Warm spawn latency regression after inode_cache removal
Removing `EfsDriver::inode_cache` was correct design (one cache,
not two) but warm `/bin/ps` load went from ~0.2ms (pre-block-cache,
BTreeMap hit) to ~6ms (block page cache lookup + inode parse). Not
urgent — 6ms is fine absolutely — but if warm spawn latency
matters later, add a tiny CPU-local inode parse cache (say 8
entries, FIFO) in EFS to avoid re-parsing the same inode on every
open.

### FAT32 full-cluster write vs RMW
Aligned full-page writes now skip RMW. Cluster writes that are
smaller than a page (e.g. 512B sector with cluster_size=1) still
RMW. Fine for FAT32's small-sector case; document or optimize if
cluster_size starts mattering.

## Ideas

### ElfSegment -> FileBacked migration
Currently ELF segments are kept in-kernel as Arc<Vec<u8>> (an entire
ELF binary per process). File-backed mmap now exists, so migrate the
ELF loader to use VmaBacking::FileBacked via MAP_PRIVATE from the
binary on disk. Saves memory (shared pages across fork, cache reuse
for re-exec), and is the prerequisite for the dynamic linker.

### Dynamic Linker (ld.so)
ELF dynamic linking: PT_INTERP, PT_DYNAMIC parsing, symbol resolution
(DT_HASH/DT_GNU_HASH), PLT/GOT lazy binding, dlopen/dlsym/dlclose.
Requires General Dynamic TLS model + DTV (dynamic thread vector).
Shared libraries share physical pages across processes via MAP_SHARED
file-backed mmap. Enables C library use, plugin systems, and shared
memory savings. Natural ordering: page cache -> file-backed mmap ->
dynamic linker.

### io_uring-style Async I/O
Shared-memory submission/completion ring between userspace and kernel.
Already have the SHM infrastructure. Very "modern OS" feature, unique among hobby OSes.

### IPv6
Full IPv6 support: different header format, NDP (replaces ARP), ICMPv6,
SLAAC/DHCPv6 for address configuration, multicast. Source-only fragmentation
(different model from IPv4). Not urgent since most targets work fine on v4,
but needed for a complete real-hardware network stack.

### virtio-net
Second NIC backend. Straightforward now that the stack and e1000e exist.
Useful for VMs where e1000e emulation is slower than paravirtual.

### EFS parallel extent reads
EfsDriver::read_via_extents reads one extent at a time. For fragmented files
spanning multiple extents, could issue all extent reads concurrently via
ncq_read_batch.

### SIGINT delivery to foreground processes
Ctrl+C in the terminal doesn't kill foreground processes. Tools that read
stdin (wc, sort, uniq, tee, tr, cat with no args) hang with no way to
interrupt them. Need proper signal delivery from PTY/terminal to the
foreground process group.

### More userspace tools
- chmod/chown (once EFS has permission support)
- printenv (alias for env)
- basename, dirname, id, whoami, date

## Fun-per-effort ranking

fsck > more tools > ElfSegment->FileBacked > dynamic linker >
async I/O > IPv6 > virtio-net

Note: fsck is the last storage-stack piece (steps 1-3 shipped).
File-backed mmap shipped; ElfSegment->FileBacked migration is the
next step in the memory/loader progression toward the dynamic linker.
