# EDOS Code Review: Drivers, DMA, Syscalls, FS/DevFS
# Date: 2026-04-06
# Status: NEW

## CRITICAL

### C1. FAT32 get_fat_entry returns unmasked raw cluster value
File: kernel/src/fs/fat32/traverse.rs:325
Status: DONE
Returns `raw` (includes reserved high nibble) instead of `val` (masked). Every FAT32 cluster-chain walk computes wrong LBAs, corrupting reads/writes.
Fix: `Ok(Some(val))` instead of `Ok(Some(raw))`

### C2. FAT32 alloc_cluster uses FAT32 byte stride for all variants
File: kernel/src/fs/fat32/write.rs:222-272
Status: DONE
The search closure computes `byte_index = cluster * 4` unconditionally. FAT16 uses stride 2, FAT12 uses 1.5 bytes. On FAT12/16 this reads wrong sectors, producing garbage free-cluster detection (and can panic on out-of-bounds reads).
Fix: Branch on `self.variant` inside the closure, matching `get_fat_entry`'s approach.

### C3. FAT12/16 find_dir_entry returns LBA as cluster number
File: kernel/src/fs/fat32/traverse.rs:128
Status: DONE
For FAT12/16 root directories, an absolute LBA is stored in the "cluster" field. When `remove_file` passes this to `cluster_to_lba()`, it applies the data-area translation to an already-translated value, corrupting an arbitrary sector on delete.
Fix: Store a sentinel for root-dir entries and skip `cluster_to_lba` in callers.

### C4. FAT32 free_cluster_chain uses fat_size_32 for all variants
File: kernel/src/fs/fat32/write.rs:667-672
Status: DONE
On FAT12/16, `fat_size_32` is 0, so the loop guard fires immediately and returns `Err(IoError)`. Every file/dir deletion on FAT12/16 leaks all clusters.
Fix: Use `fat_size_16` for FAT12/16 variants.

### C5. AHCI setup_command_table underflow when buffer_size == 0
File: kernel/src/drivers/ahci/port.rs:722
Status: DONE
`(buffer_size - 1) as u32` wraps to `0xFFFF_FFFF` in release (panic in debug). Called with `buffer_size = 0` for `flush_cache`. Tells the HBA to DMA ~4 GB.
Fix: Guard PRDT setup on `buffer_size > 0`, set `prdtl = 0` when no data buffer.

### C6. sys_pipe FD leak on copy-out failure
File: kernel/src/syscalls/mod.rs:617-640
Status: DONE
Both FDs are inserted into the table before `try_copy_to_user`. If the write faults, the function returns error but leaves two unreachable pipe ends in the FD table forever.
Fix: Close both FDs on the error path before returning.

## HIGH

### H1. sys_poll unbounded heap allocation from untrusted count
File: kernel/src/syscalls/io.rs:608
Status: DONE
`vec![...; count]` with no cap. User can pass huge values to exhaust kernel heap.
Fix: Cap at e.g. 1024 and return EINVAL above that.

### H2. Block device cache miss coalescing assumes contiguous misses
File: kernel/src/fs/block_device.rs:52-53
Status: DONE
Non-consecutive cache misses (e.g., LBA 5 and 7 both missing, 6 cached) are read as a single contiguous range from the first miss. LBA 7's buffer position gets wrong data.
Fix: Group miss ranges into contiguous sub-ranges, or issue one read per miss.

### H3. memfs remove_dir has inverted kind check
File: kernel/src/fs/memfs/mod.rs:239
Status: DONE
Checks `kind != File` and returns `NotAFile`, meaning it rejects directories and would delete files. Completely backwards.
Fix: `if child.file.kind != FileKind::Directory { return Err(Error::NotADir); }`

### H4. DMA buffer recycling: stale cached physical address
File: kernel/src/drivers/dma.rs:107
Status: WONTFIX
Recycled buffers retain their virtual-to-physical mapping (not unmapped/remapped), so the cached phys_addr remains correct. Not a real bug with current code.

### H5. HPET ticks_to_nanos overflows u64 for large tick deltas
File: kernel/src/drivers/hpet/instant.rs:15-16
Status: DONE
`ticks * self.frequency` overflows u64 silently for large deltas (~2^63 ticks at 70M fs/tick), producing wrong timeout/sleep durations.
Fix: Use u128 for the intermediate product: `((ticks as u128 * self.frequency as u128) / 1_000_000) as u64`

### H6. MSI address encodes LAPIC ID without masking
File: kernel/src/drivers/msi/mod.rs:45
Status: DONE
`lapic_id << 12` can corrupt the 0xFEE prefix if the ID exceeds 8 bits (x2APIC mode). MSI goes to wrong CPU or nowhere.
Fix: `(lapic_id & 0xFF) << 12`

### H7. AHCI check_errors clears all IS bits, not just TFES
File: kernel/src/drivers/ahci/port.rs:666-683
Status: DONE
Writes back full `is` value, clearing DHRS/DSS/etc. that `wait_for_command_completion` needs. Follow-on commands see IS=0 and time out instead of fast error return.
Fix: Write only PORT_IS_TFES.

### H8. sys_shm_map no validation on addr_hint
File: kernel/src/syscalls/shm.rs:67-143
Status: DONE
User-supplied address is used directly without alignment or kernel-space range check. User can map shared memory into kernel space.
Fix: Validate page alignment and addr_hint < KERNEL_SPACE_BASE.

### H9. MAP_PHYSICAL no alignment check, no rollback on partial failure
File: kernel/src/syscalls/memory.rs:42-88
Status: DONE
Unaligned phys_addr causes wrong frame mapping. Partial mapping failure leaks already-mapped pages (no MemoryMapping recorded).
Fix: Check phys_addr & 0xFFF == 0, and roll back on error like sys_shm_map does.

### H10. sys_window_send_event allows any process to inject events into any window
File: kernel/src/syscalls/window.rs:393-425
Status: WONTFIX
No ownership check possible without a WM privilege system -- the WM and taskbar both send events to windows they don't own. Part of the broader M4 design gap (deferred).

## MEDIUM

### M1. sys_dup TOCTOU: scan and insert under separate locks
File: kernel/src/syscalls/mod.rs:661-666
Status: DONE
Another thread sharing the FD table can race between the lowest-free scan and insert.
Fix: Single lock hold with allocate_lowest_fd.

### M2. sys_open ignores O_TRUNC and access mode flags
File: kernel/src/syscalls/io.rs:444-445
Status: WONTFIX
Requires adding truncate_file to the FileSystem trait and implementing for FAT32/memfs. Feature addition, not a mechanical fix. Deferred.

### M3. memfs write_bytes panics when partial write within existing content
File: kernel/src/fs/memfs/mod.rs:144-148
Status: DONE
`copy_from_slice(&data[..slice.len()])` panics if data.len() < slice.len().
Fix: `let n = slice.len().min(data.len())`.

### M4. AHCI stop_port and initialize_port missing &raw const on volatile reads
File: kernel/src/drivers/ahci/port.rs:121, kernel/src/drivers/ahci/controller.rs:308
Status: DONE
Creates Rust references to MMIO registers (UB). All other accesses use &raw const/mut.
Fix: Change to &raw const.

### M5. memfs next_id overflow
File: kernel/src/fs/memfs/mod.rs:174
Status: DONE
u32 wraps after 4B creations, silently reusing IDs.
Fix: checked_add with error return.

### M6. sys_write unbounded kernel buffer allocation
File: kernel/src/syscalls/io.rs:95-186
Status: DONE
`vec![0u8; count]` where count is user-controlled with no cap.
Fix: Cap at e.g. 1 MiB.

### M7. sys_spawn argv cap off-by-one
File: kernel/src/syscalls/mod.rs:804
Status: DONE
argv_storage is pre-seeded with argv[0], so the == MAX_ARGC check allows one extra arg.
Fix: Remove the redundant && argv_storage.len() == MAX_ARGC condition; rely on terminated flag.

### M8. PS/2 force_push drops oldest scancode
File: kernel/src/drivers/mod.rs:52
Status: DONE
Under sustained input, oldest scancodes are lost, which can cause stuck modifier keys (missed key-up).
Fix: Use push (drop newest) or increase queue size.

### M9. FAT32 write.rs redundant FileTime::now() call
File: kernel/src/fs/fat32/write.rs:160
Status: DONE
Dead code shadowing the previous binding. Wastes an RTC read.
Fix: Remove the second `let current_time = FileTime::now()`.

### M10. BlockDevice constructed twice in Fatfs::new
File: kernel/src/fs/fat32/mod.rs:82
Status: DONE
First one (with its LRU cache) is thrown away.
Fix: Construct once, reuse for both boot sector read and storage.

## LOW

### L1. Path::parse accepts relative paths and never returns Err
File: kernel/src/fs/path.rs:22-29
Status: OPEN
ParseError is dead code. Relative paths silently accepted. "../" components handled by normalize() but contract is unclear.
Fix: Validate leading '/' at minimum.

### L2. VFS startup loop in fs_main_thread iterates empty FS_WORKER_MAILBOXES
File: kernel/src/fs/mod.rs:633-651
Status: OPEN
Dead code -- no mounts exist at that point.
Fix: Remove the loop.

### L3. FAT32 generate_short_name loop has no iteration bound
File: kernel/src/fs/fat32/write.rs
Status: OPEN
The counter loop for numeric suffix generation has no termination guard.
Fix: Bound at e.g. 999999 and return error.

### L4. procfs try_lock silently omits thread info on contention
File: kernel/src/fs/procfs/mod.rs:474
Status: OPEN
If ThreadInfo lock is held, user info is silently omitted from /proc/<tid>/status.
Fix: Document the behavior or retry.

### L5. AHCI driver main loop busy-polls with no sleep/park
File: kernel/src/drivers/ahci/mod.rs:205-245
Status: OPEN
Polls HBA IS register in a tight loop. On quiescent system wastes CPU time.
Fix: Park until woken by AHCI interrupt.
